# Контур Work

Приватная система управления работой на собственном сервере: проекты, задачи,
планирование, база знаний, командный чат и ИИ-агенты в одном рабочем пространстве.
Русский интерфейс, отдельные права пользователей и групп, работа с компьютера
и телефона. Основные данные хранятся в MySQL или PostgreSQL на выбор,
файлы — в приватном S3-хранилище.

**Версия 0.23.1** · [Трайбы и доступ](docs/TRIBES-AND-ACCESS.md) · [Изменения](docs/RELEASE-0.23.1.md) · [Выбор БД](docs/DATABASES.md) ·

## Возможности

| Раздел | Что можно делать |
| --- | --- |
| Компания и трайбы | Собственное пространство каждого трайба, лидер и делегирование прав. Закрытые проекты с владельцем, личными и групповыми назначениями. |
| Согласования ИИ | Отдельная очередь шагов сценариев и предложенных действий, назначенных сотруднику. |
| Проекты и задачи | Вести эпики, истории, задачи и подзадачи; работать с канбаном, бэклогом, спринтами, Гантом и релизами. Настраивать процессы, поля, лимиты этапов, исполнителей и зависимости. |
| Планирование | Готовить будущие проекты и инициативы внутри действующих. Связывать их с целями, оценивать эффект и усилия, согласовывать состав. Запланированные карточки сразу видны на доске в колонке «Планируется» при наличии прав. |
| Общая карта | Видеть планы и текущие задачи на одной шкале, зависимости и прогноз загрузки. Примерять сдвиг сроков, затем сохранять только выбранные изменения. |
| ИИ-агенты | Собирать сценарий из блоков: триггеры, источники, анализ, условия, действия и согласование. Перемещать блоки, выбирать стороны стрелок, использовать версии общих частей сценария и разбирать выполненные шаги. |
| ИИ для планов | Получать предложения эпиков, задач, зависимостей и критериев готовности. Сохранять только выбранные предложения после проверки. |
| База знаний | Создавать пространства команд, редактировать статьи, хранить версии и назначать отдельные права. |
| Чат и встречи | Общаться в личных и проектных чатах, создавать постоянные комнаты, обмениваться файлами, проводить и планировать видеовстречи. Запись и расшифровка подключаются отдельно. |
| Отчёты и цели | Настраивать дашборды, отслеживать сроки, загрузку, цели и ключевые результаты; работать с тестированием и результатами Allure. |
| Личное пространство | Закреплять проекты, доски, планы и статьи в избранном, менять их порядок, работать с уведомлениями и мобильным PWA. |
| Администрирование | Управлять ролями и группами, LDAP/AD, OIDC, SMTP, API-токенами, журналом действий и автоматизациями. |

Интеграции включают подписанные webhooks, корпоративные мессенджеры,
календари и инструменты разработки. Существующий перенос из Jira описан
в [отдельном руководстве](docs/JIRA-TRANSFER.md); в версии 0.21 он не расширялся.

Адреса зеркал apk, apt, Go и Node.js/npm настраиваются через `.env`: [источники сборки](docs/BUILD-SOURCES.md).

## Как устроена система

| Компонент | Назначение |
| --- | --- |
| Next.js 16 / React 19, Node.js 22.13+ | Интерфейс, API и серверная логика; JavaScript ESM. |
| MySQL 8.4 или PostgreSQL 18 | Проекты, задачи, права, история, настройки и журнал запусков. |
| Redis / BullMQ | Очереди, события и фоновые задания. |
| S3 / MinIO | Приватные вложения и записи встреч. |
| LiveKit / Egress | Видеосвязь, демонстрация экрана и серверная запись. |
| `worker` / `recording-worker` | Автоматизации, ИИ, интеграции, обработка записей и расшифровка. |

Варианты поставки используют один образ приложения:

- **Docker Compose** — один сервер, выбранная БД, Redis, MinIO и LiveKit.
- **Kubernetes / Helm** — масштабирование приложения и медиасервисов с внешними
  MySQL/PostgreSQL, Redis и S3. Отказоустойчивость зависит и от этих внешних компонентов.

## Запуск в Docker

Для первого запуска нужны Git, Docker Engine 24+ и Docker Compose v2.24.4+.
Ориентир для приложения без записи встреч — 4 vCPU, 8 ГБ памяти и SSD;
запись и большие видеовстречи требуют дополнительных ресурсов.

### 1. Получите проект и создайте конфигурацию

```bash
git clone https://github.com/Kertis90/kontur.git
cd kontur
cp .env.example .env
```

В PowerShell вместо последней команды: `Copy-Item .env.example .env`.
Для приватного репозитория нужен доступ вашей учётной записи GitHub.
Если `.env` уже существует, сохраните его значения и добавьте только отсутствующие
параметры из примера.

### 2. Задайте свои реквизиты в `.env`

| Параметры | Что указать |
| --- | --- |
| `MYSQL_PASSWORD`, `MYSQL_ROOT_PASSWORD` | Два разных надёжных пароля для установки с MySQL. |
| `POSTGRES_PASSWORD`, `POSTGRES_ADMIN_PASSWORD` | Два разных надёжных пароля для установки с PostgreSQL. |
| `S3_SECRET_KEY` | Пароль файлового хранилища MinIO. |
| `AUTH_SECRET` | Случайный секрет сессий длиной не менее 32 символов. |
| `APP_ENCRYPTION_KEY` | 64 шестнадцатеричных символа для шифрования секретов и сохранённых входов ИИ. |
| `LIVEKIT_API_SECRET` | Случайный секрет видеосервера длиной не менее 32 символов. |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD`, `ADMIN_NAME` | Данные первого владельца рабочего пространства. |
| `APP_URL`, `LIVEKIT_WS_URL` | Для локального запуска оставьте адреса из примера; для сервера задайте публичные HTTPS/WSS-адреса. |

Если установлен OpenSSL, секреты можно создать так:

```bash
openssl rand -base64 48
openssl rand -hex 32
openssl rand -base64 36
```

Это отдельные значения для `AUTH_SECRET`, `APP_ENCRYPTION_KEY` и
`LIVEKIT_API_SECRET`. Остальные пароли создайте независимо.
Ключ шифрования сохраните вместе с защищённой копией конфигурации:
без него нельзя прочитать ранее зашифрованные данные. `.env` исключён из Git.

### 3. Запустите сервисы

По умолчанию используется MySQL (`DB_ENGINE=mysql`):

```bash
docker compose up -d --build --wait
docker compose ps -a
curl --fail http://localhost:3000/api/health
```

Для новой установки на **PostgreSQL** задайте `DB_ENGINE=postgres`,
`POSTGRES_PASSWORD` и отдельный `POSTGRES_ADMIN_PASSWORD`, затем вместо
команды запуска выше выполните:

```bash
docker compose -f compose.yaml -f compose.postgres.yaml up -d --build --wait
```

Оба варианта используют один образ приложения. Выбор БД не переносит существующие
данные. Миграции, разработка, Helm и копии описаны в [руководстве по БД](docs/DATABASES.md).
Во всех последующих Compose-командах PostgreSQL указывайте те же два файла.

Откройте **[http://localhost:3000](http://localhost:3000)** и войдите с данными
`ADMIN_EMAIL` / `ADMIN_PASSWORD`. Одноразовый сервис `migrate` подготавливает
схему и начальные данные до запуска приложения. В новой установке создаются
владелец и демонстрационный проект NOVA. При повторном seed существующему
владельцу восстанавливаются роль и активный статус; его пароль не сбрасывается.

Состояние `Exited (0)` для `migrate` и `minio-init` означает успешное завершение.
MinIO и его клиент также собираются из закреплённых официальных исходников:
первая сборка занимает дополнительное время. Готовые образы можно разместить
в своём реестре — [подробности сборки хранилища](deploy/storage/README.md).
Для закрытого контура адреса пакетов npm, Alpine, Debian, модулей Go и исходников
с GitHub задаются отдельными параметрами `.env` — см. [релиз 0.22.1](docs/RELEASE-0.22.1.md).
При проблемах проверьте журналы:

```bash
docker compose logs --tail=100 migrate app worker
```

Для публичного сервера настройте домены, HTTPS, доступные порты и профиль
`gateway` по [инструкции Docker](deploy/standalone/README.md).
Камера, микрофон и PWA требуют HTTPS; `localhost` допускается для разработки.
Остановка с сохранением данных: `docker compose stop`.

## Первые шаги после входа

1. Добавьте сотрудников и группы, назначьте проектные роли.
2. Создайте проект и настройте его процесс либо изучите демонстрационный NOVA.
3. В разделе «Планирование и инструменты → Планы и идеи» подготовьте инициативу,
   эпики и задачи. Для участников отдельно назначьте права планирования.
4. Откройте общую карту, проверьте зависимости и сроки. «Начать работу» в плане
   создаёт обычную рабочую карточку с сохранением связи с планом.
5. Закрепите нужные проекты, доски, планы и статьи в избранном.

Планы будущих проектов доступны назначенным участникам. После привязки к рабочему
проекту действуют его права. Изменение состава или сроков делает прежнее
согласование устаревшим. Подробности — в [руководстве по планированию](docs/PLANNING.md).

## Настройка ИИ

В **Администрирование → Искусственный интеллект** добавьте подключение:
совместимый endpoint, ключ и модель, лимит контекста и бюджет. Ключи хранятся
зашифрованно; в Git их добавлять не требуется. Можно использовать свой сервер
модели или внешний сервис. Пустые параметры расшифровки не мешают обычной работе.

Создайте агента для проекта, выберите источники и соберите сценарий. Схема
сохраняется как черновик; публикация — отдельное действие. Сначала запустите
проверку и изучите входы, результаты, выбранные ветви и расход на блоках.
Повтор по прежним данным требует актуальных прав и версий источников.
Проверки обращаются к модели и расходуют бюджет, но не применяют предложенные действия.

Сведения передаются выбранному провайдеру только в пределах доступных источников.
Для автоматических запусков нужны работающий worker и права исполнителя.
ИИ-помощник плана предлагает состав, а создание выбранных карточек подтверждает
пользователь. [Конструктор агентов](docs/AI-AGENTS.md) ·
[Бюджеты и качество](docs/AI-BUDGETS-AND-QUALITY.md).

## Доступ и API

Права назначаются пользователям и группам на рабочее пространство и проекты.
У планирования, пространств знаний, комнат, конференций и ИИ есть дополнительные
проверки доступа. Закрепление ссылки или сохранённый запуск не выдаёт новых прав.
Системные владелец и администратор сохраняют административный доступ.

Раздел **Мой API** позволяет выпустить персональный токен и посмотреть примеры
запросов. Сервер совместно проверяет разрешения токена, политику пользователя
и его текущие права. Машиночитаемая спецификация: `GET /api/openapi.json`.
[API](docs/API.md) · [Безопасность](docs/SECURITY.md).

## Обновление и резервные копии

Перед обновлением сохраните MySQL, файлы S3 и конфигурацию с ключами.
Зашифрованную копию MySQL и учебное восстановление можно выполнить штатными
скриптами: [эксплуатация и восстановление](docs/OPERATIONS.md).
Копия только базы не содержит вложений и записей встреч.

Обновление включает новый образ приложения, миграции, app и оба worker.
Порядок остановки процессов и восстановления после частично применённой миграции
описан в [руководстве по обновлению БД](docs/DATABASE-UPGRADES.md).
Для 0.21 добавлены миграции **038–043**; выпущенные **001–037** не изменяются.
Новых обязательных параметров окружения нет.

Не используйте `docker compose down -v` для обычной остановки: команда удаляет
тома с данными. Восстановление проверяйте на отдельной установке.

## Kubernetes

Подготовьте свой реестр образов, внешний MySQL 8.4 или PostgreSQL 18, Redis и S3, Secret с
реквизитами, домены и TLS. Настройте ресурсы приложения и медиасервисов в values.
Команды сборки, установки Helm, настройки сети, мониторинга и обновления:
[руководство Kubernetes](deploy/helm/kontur-work/README.md).

## Разработка и проверки

Нужны Node.js **22.13+**, npm и Docker Compose v2. Используйте версии зависимостей
из `package-lock.json`:

```bash
npm ci
npm test
npm run quality
npm run build
git diff --check
```

Серверные тесты не требуют живой MySQL. Интеграционные и браузерные проверки
работают на отдельном одноразовом стенде с собственными портами и тестовыми
данными. Полный порядок — в [руководстве разработчика](docs/DEVELOPMENT.md).

Для разработки на компьютере используйте `.env.development.example` и
`compose.dev.yaml`: приложение и worker запускаются на хосте, инфраструктура —
в Docker. `.env.example` предназначен для полного Compose-профиля.
У скриптов Node окружение передаётся через `node --env-file=.env`; Next.js
читает `.env` самостоятельно. Задачи и отладка VS Code входят в репозиторий.

```text
app/                       страницы, стили и вход API
src/components/            интерфейс разделов и визуального конструктора
src/lib/                   данные, права, планирование, ИИ и интеграции
scripts/migrations/        последовательные миграции MySQL
scripts/                   фоновые процессы, проверки и резервирование
tests/browser/             проверки интерфейса на компьютере и телефоне
deploy/                    Docker, Helm, мониторинг и тестовые стенды
docs/                      руководства, решения и история версий
```
