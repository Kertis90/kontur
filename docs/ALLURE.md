# Allure Report

В «Тестирование → Allure» и «Интеграции → Allure» можно сохранять результаты автотестов как завершённые прогоны Контур. Поддерживается стандартный формат [Allure test result file](https://allurereport.org/docs/how-it-works-test-result-file/). Это импорт результатов Allure Report; синхронизация каталога Allure TestOps через его API в эту версию не входит.

## Подключение

1. Выберите проект, создайте подключение. Нужно право `qa.manage`.
2. Укажите базовый адрес ваших отчётов, например `https://allure.example/reports/`. Ссылки импортируемых запусков должны относиться к этому origin и пути. Поле можно оставить пустым, если ссылки не нужны. Контур не скачивает содержимое URL.
3. По умолчанию сопоставление идёт по `historyId` с полем «Ключ автотеста» тест-кейса. Можно выбрать `fullName` или `testCaseId`. Для параметризованных вариантов к этим ключам добавляется хеш параметров. UUID выполнения не используется как ключ кейса. Точный ключ виден в предпросмотре.
4. При необходимости разрешите создание отсутствующих кейсов. Пользователю импорта всё равно понадобится `qa.manage`. Для существующих кейсов достаточно `qa.execute`.
5. Загрузите `*-result.json`, проверьте выборку и нажмите «Импортировать». Поддерживается до 200 файлов и 2,8 МБ файлов за раз; API ограничен 3 МБ. Для больших наборов выделяйте отдельные подключения/прогоны по компонентам или CI jobs.

Все подключения изолированы по проекту. Подключение можно приостановить, не удаляя историю. Планы и прогоны сохраняются в общей библиотеке тестирования. Из `failed` и `broken/unknown` можно создать связанную задачу; повторное нажатие открывает уже созданный дефект. Нужны `qa.execute` и `task.create`.

## CI

Выполняйте скрипт из каталога исходного кода Контур на CI runner с Node.js 22.13+; сам скрипт не требует `npm install`. Если копируете только скрипт в репозиторий тестов, сохраните его как `scripts/import-allure.mjs`.

Переменные:

| Переменная | Значение |
|---|---|
| `KONTUR_URL` | HTTPS-адрес вашей установки |
| `KONTUR_TOKEN` | Секрет CI: персональный токен пользователя интеграции |
| `KONTUR_ALLURE_CONNECTION_ID` | ID подключения, виден в интерфейсе |
| `KONTUR_ALLURE_LAUNCH_ID` | Уникальный стабильный ID запуска в подключении |
| `KONTUR_ALLURE_TITLE` | Название прогона, необязательно |
| `KONTUR_ALLURE_REPORT_URL` | Ссылка на размещённый отчёт, необязательно |

Администратор должен разрешить пользователю API. Scope токена и политики пользователя: `quality:write`; права проекта: `project.browse`, `qa.execute`, при создании новых кейсов также `qa.manage`. Для создания дефектов через отдельный API-метод добавьте `tasks:write` и `task.create`.

```sh
export KONTUR_URL=https://kontur.example
export KONTUR_ALLURE_CONNECTION_ID=1
export KONTUR_ALLURE_LAUNCH_ID=pipeline-401
export KONTUR_ALLURE_TITLE='Автотесты · сборка 401'
# KONTUR_TOKEN передаётся из защищённого секрета CI.
node scripts/import-allure.mjs ./allure-results
```

При запуске из другого каталога укажите абсолютные пути к скрипту и результатам. Скрипт не генерирует HTML-отчёт и не публикует его: это остаётся шагом вашей CI-сборки. Он не следует HTTP redirects. Для локального доверенного HTTP-стенда предусмотрен явный `KONTUR_ALLOW_HTTP=true`; в рабочих контурах используйте HTTPS.

Пример шага GitHub Actions после получения результатов (Node.js и checkout должны быть подготовлены предыдущими шагами):

```yaml
- name: Import results into Kontur
  if: always()
  env:
    KONTUR_URL: ${{ vars.KONTUR_URL }}
    KONTUR_TOKEN: ${{ secrets.KONTUR_TOKEN }}
    KONTUR_ALLURE_CONNECTION_ID: '1'
    KONTUR_ALLURE_LAUNCH_ID: ${{ github.run_id }}-${{ github.run_attempt }}-linux
    KONTUR_ALLURE_TITLE: CI ${{ github.run_number }}
  run: node scripts/import-allure.mjs ./allure-results
```

Пример команды в GitLab CI job с настроенными защищёнными переменными `KONTUR_URL`, `KONTUR_TOKEN`, `KONTUR_ALLURE_CONNECTION_ID` и артефактами тестового job:

```yaml
script:
  - export KONTUR_ALLURE_LAUNCH_ID="${CI_PIPELINE_ID}-${CI_JOB_ID}"
  - node scripts/import-allure.mjs ./allure-results
```

Для повторной отправки *того же пакета* сохраните прежний ID и название. Повтор ID с теми же нормализованными результатами возвращает `replayed: true`. Изменённое содержимое, название или URL с тем же ID дают `409`. Новый реальный перезапуск тестов должен иметь новый ID.

## Результаты и ограничения

- Повторные попытки объединяются по стабильному ключу; выбирается последняя по `stop`/`start`. При одинаковых временных метках используется детерминированный порядок. Точный дубликат UUID отбрасывается, противоречащие результаты одного UUID отклоняются.
- `passed → passed`, `failed → failed`, `broken/unknown → blocked`, `skipped → skipped`. Успех после ошибки помечается нестабильным; учитывается `statusDetails.flaky`.
- Сохраняются ограниченные тексты ошибок/стека, до 100 шагов с глубиной до 6 уровней, метки suite/feature/story/severity и параметры. Значения параметров с `mode=hidden/masked` не сохраняются в метаданных. Ошибки, имена, шаги и trace — исходный текст тестов: настройте тесты так, чтобы они не писали в них секреты.
- Бинарные вложения, изображения и видео остаются в хранилище Allure. Контур хранит их количество и ссылку на отчёт. Запросы внешней авторизации для отчёта не обходятся.
- Кейсы в архиве блокируют импорт. Если ключи отличаются только регистром/диакритикой при текущей MySQL collation, используйте `historyId`.
- Триггер агента `quality.allure.imported` создаётся в той же транзакции, что и импорт. При точном повторе импорта нового события нет.

Все методы, примеры запросов и права опубликованы в «Мой API», а также в `/api/openapi.json`.
