# Интеграции

Откройте «Интеграции» в боковом меню или в администрировании. Здесь находятся каталог, подключения уведомлений, GitHub/GitLab и прежние webhooks/API. Права назначаются обычными ролями пользователям и вложенным группам.

## Поддерживаемые подключения

| Сервис | Что работает | Что указать |
| --- | --- | --- |
| Telegram | Уведомления в чат, группу, канал или тему | Токен бота, Chat ID / @имя канала, необязательный ID темы |
| Mattermost | Сообщения в канал входящего webhook | HTTPS URL вида `https://chat.example.ru/hooks/…` |
| Slack | Сообщения в канал Incoming Webhook | HTTPS URL на `hooks.slack.com` или `hooks.slack-gov.com` |
| Webhook | JSON и подпись HMAC-SHA256 для n8n, Make и своих сервисов | HTTPS URL и секрет подписи от 16 символов |
| GitHub / GitLab | Коммиты, ветки, PR/MR и сборки в карточке задачи по ключу | URL репозитория; Контур выдаёт адрес входящего webhook и секрет |

Четыре подключения уведомлений новые; GitHub/GitLab используют ранее реализованный входящий обработчик. Это не двусторонняя синхронизация задач. Почта, LDAP/OIDC, S3, телефония и профили ИИ сохраняют свои отдельные настройки.

### Первое подключение

1. Выберите сервис в каталоге, задайте название и один активный проект. Для другого проекта или получателя создайте отдельное подключение.
2. Укажите реквизиты. После сохранения секреты скрыты; для замены отметьте «Заменить сохранённые реквизиты». Сохранённые токены и полные webhook URL не возвращаются через API.
3. Выберите события: создание/изменение задачи, приближение срока, новый комментарий. Напоминание о сроке создаёт существующий ежедневный worker для незавершённых задач со сроком от сегодня до двух дней вперёд; это не отдельный SLA-таймер.
4. Включите доставку. При создании переключатель по умолчанию выключен. События старше последнего сохранения подключения не подхватываются.
5. Нажмите «Тестовая отправка» и затем «Отправить сообщение». Это реальное сообщение в настроенный канал с фиксированным текстом, без данных проекта. HTTP 202 означает постановку в очередь. Результат показывает журнал.

Для Telegram создайте бота через BotFather, добавьте его в выбранную группу/канал и разрешите отправку. Для личного чата пользователь должен сначала начать диалог с ботом. Chat ID и ID темы берутся из данных Bot API; Контур не читает переписку Telegram и не устанавливает webhook бота. Для Mattermost/Slack создайте входящий webhook на стороне сервиса и выберите там канал; Контур не переопределяет получателя из события задачи.

Протоколы проверены по официальной документации: [Telegram sendMessage](https://core.telegram.org/bots/api#sendmessage), [Mattermost Incoming Webhooks](https://developers.mattermost.com/integrate/webhooks/incoming/), [Slack Incoming Webhooks](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/).

## Права

| Действие | Права рабочего пространства | Права проекта |
| --- | --- | --- |
| Каталог и список | `integration.view` или `integration.manage` | `project.browse` |
| Создать, изменить, включить, выключить, удалить | `integration.manage` | `project.admin`, активный проект |
| Читать журнал | право просмотра + `integration.logs` | `project.browse` |
| Тестовая отправка | право просмотра + `integration.test` | `project.browse` |
| Повторить ошибочную доставку | право просмотра + `integration.logs` + `integration.test` | `project.admin`, активный проект |

Владелец и администратор получают права по существующей модели. У остальных новые права не появляются автоматически; настройте роли и назначения групп. Права настройки интеграций не открывают все проекты.

Отправка выполняется от имени последнего редактора подключения. Worker перед каждой попыткой проверяет активность пользователя, `integration.manage` и `project.admin`. Утрата прав, архивирование/удаление проекта, удаление или перемещение задачи отменяют отправку. Для теста дополнительно проверяются текущие права инициатора. Получатель видит ключ и название задачи; описание, комментарий, вложения, записи встреч и поля пользователей в новых уведомлениях не передаются.

## Доставка и журнал

- Подписки ограничены одним проектом и явно выбранными событиями. Сохраняется до 200 подключений на пространство.
- Существующий outbox создаёт доставку на пару «подключение + UUID события»; уникальный индекс исключает повторную постановку при повторной обработке outbox.
- Отдельный цикл существующего `worker` читает очередь MySQL каждые 2 секунды: до 20 записей за проход, до 4 сетевых запросов параллельно на worker. Атомарный захват с арендой на 2 минуты позволяет использовать несколько реплик. Незавершённые аренды восстанавливаются.
- Сетевой запрос, включая DNS, ограничен 10 секундами; ответ — 64 КиБ. Перенаправления не выполняются.
- При сетевом сбое, HTTP 408/429/5xx — максимум 5 автоматических попыток: через 1, 5, 15 и 60 минут. Числовой Retry-After / Telegram retry_after учитывается до 24 часов. Прочие HTTP-ошибки требуют исправления настроек или действий оператора.
- В журнале: состояние, код ошибки, HTTP-код, суммарное число попыток, время и UUID. По 50 записей, фильтр состояния, обновление каждые 5 секунд. Ответы провайдеров, URL и токены в журнал не записываются.
- Повтор вручную возможен спустя 30 секунд после ошибки, только для прежней версии подключения. Счётчик не обнуляется: после пятой попытки каждый ручной повтор даёт одну дополнительную попытку.
- Перед первой сетевой отправкой формируется снимок текущего ключа и названия задачи; он хранится зашифрованным и повторно используется при повторах. Проверка существования задачи и прав выполняется заново.
- Сохранение, пауза и удаление отменяют очередь прежней версии. Уже начавшийся сетевой запрос остановить гарантированно нельзя. Принятые внешним сервисом сообщения не удаляются автоматически.

Гарантия доставки — **at least once**: если сервис принял сообщение, а worker прервался до фиксации ответа, сообщение может повториться. Telegram/Slack/Mattermost не предлагают общей идемпотентности этих методов. Собственный webhook-получатель должен дедуплицировать UUID. Успешный ответ означает принятие сервисом, не прочтение человеком. Журнал сохраняется до удаления подключения; при больших объёмах планируйте размер MySQL.

Прежние webhooks находятся в отдельной вкладке и используют прежний механизм. Они не перенесены автоматически, чтобы не включить дополнительную отправку. Новый журнал, сетевые ограничения и повторная доставка относятся к подключениям из каталога. Новые уведомления не отправляются об удалении задач, встречах, SLA-нарушениях или изменении репозитория.

## Сеть и развёртывание

Дополнительный сервис, брокер или пакет не требуется: используются текущие приложение, worker, MySQL и Redis. Миграция `021_integrations.sql` создаёт две таблицы без изменения старых миграций и без триггеров. Приложение, migrate и все worker должны использовать одинаковую версию 0.13.0.

Разрешите worker исходящий DNS и HTTPS к нужным сервисам. По умолчанию запрещены внутренние, loopback, link-local, metadata, multicast и специальные диапазоны. DNS проверяется перед каждой отправкой, проверенный IP закрепляется за сокетом; TLS проверяет исходное имя сервиса. Отключения проверки сертификата нет.

Для внутреннего Mattermost/webhook с доверенным HTTPS-сертификатом укажите точные hostname:

```dotenv
INTEGRATION_ALLOWED_PRIVATE_HOSTS=chat.company.internal,automation.company.internal
```

Compose передаёт эту переменную приложению и worker. В Helm используйте:

```yaml
integrations:
  allowedPrivateHosts: "chat.company.internal,automation.company.internal"
```

Разрешение действует только для RFC1918 и IPv6 ULA. Wildcard не поддерживается; loopback и metadata остаются закрытыми даже в списке. Настройки сети кластера применяются независимо. Секреты шифруются штатным `APP_ENCRYPTION_KEY`; сохраните его при обновлении и в резервной копии.

## API

Документация методов встроена в «Мой API», `/api/docs` и `/api/openapi.json`. Для токенов требуются разрешение API у пользователя, подходящий scope в политике и токене, а также перечисленные выше функциональные права.

| Метод и путь | Scope | Назначение |
| --- | --- | --- |
| GET `/api/work/integrations` | `integrations:read` | Каталог и подключения доступных активных проектов |
| POST `/api/work/integrations` | `integrations:write` | Создать подключение |
| PUT `/api/work/integrations/{id}` | `integrations:write` | Сохранить полную конфигурацию |
| PATCH `/api/work/integrations/{id}` | `integrations:write` | Включить/выключить |
| DELETE `/api/work/integrations/{id}` | `integrations:write` | Удалить подключение и журнал |
| POST `/api/work/integrations/{id}/test` | `integrations:send` | Поставить тест в очередь |
| GET `/api/work/integrations/{id}/deliveries` | `integrations:read` | Журнал; `status`, `offset` |
| POST `/api/work/integrations/{id}/deliveries/{deliveryId}/retry` | `integrations:send` | Повторить ошибочную отправку |

Новые scopes исключены из автоматически выдаваемых по умолчанию. Для изменения/удаления и тестовой отправки передайте `version_number` из списка. Несовпадение — HTTP 409. DELETE принимает JSON `{ "version_number": 1 }`. PUT требует все несекретные поля; без `credentials` сохраняет прежние реквизиты. Проект и провайдер у существующего подключения не меняются.

Пример собственного webhook; замените значения на свои:

```json
{
  "name": "Автоматизация проекта",
  "provider": "webhook",
  "project_id": 1,
  "enabled": false,
  "event_types": ["task.created", "comment.created"],
  "config": {},
  "credentials": {
    "url": "https://automation.example.ru/hooks/kontur",
    "secret": "REPLACE_WITH_RANDOM_SECRET"
  }
}
```

Для Mattermost/Slack `credentials` содержит только `url`; для Telegram — `token`, а `config` содержит `chat_id` и необязательный положительный `message_thread_id`.

Подписанный webhook получает тело:

```json
{
  "id": "a083190c-370d-4ab4-b550-f0ea1c47a0d4",
  "type": "task.created",
  "created_at": "2026-09-15 10:00:00",
  "data": { "task_id": 42, "project_id": 1, "key": "PROD-42", "title": "Подготовить релиз" }
}
```

`created_at` — время создания доставки в UTC. Заголовки: `X-Kontur-Event`, `X-Kontur-Delivery` и `X-Kontur-Signature-256: sha256=<hex>`. Проверяйте HMAC-SHA256 по исходным байтам тела до JSON.parse, сравнивайте подпись за постоянное время и сохраняйте UUID для дедупликации. Возвращайте 2xx после надёжного принятия события. Тест имеет type `integration.test` и data с фиксированным текстом.

## Проверка и дальнейшее развитие

Автоматические тесты проверяют адаптеры без сетевой отправки, права и scopes, защиту адресов/DNS, сокрытие секретов, дедупликацию, аренду, повторы, неизменность снимка и конфликты версий. Реальные каналы, MySQL 8.4 и отображение интерфейса требуют проверки в целевой среде.

Следующие отдельные расширения: календарные подключения CalDAV/Google/Microsoft для встреч, уведомления о SLA и релизах, входящие команды ботов с проверкой личности и прав, сопоставление внешних задач для двусторонней синхронизации. Они в 0.13.0 не включены.
