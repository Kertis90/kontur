# Инструменты конференций

Во встрече вкладка «Инструменты» содержит опросы, комнаты обсуждений, зал ожидания и посещаемость. Организатор и сотрудники с `conference.manage` управляют этими функциями. Остальные могут голосовать и входить в назначенные комнаты. Доступ к самой встрече проверяется отдельно: приглашение, авторство, модерация или действующая ссылка для авторизованного сотрудника того же пространства.

При планировании можно включить зал ожидания. `POST /api/conferences/{id}/token` вернёт `waiting:true` без медиатокена, пока модератор не допустит сотрудника. Клиент повторяет запрос через 3 секунды. Отказ возвращает 403. Включение ожидания во время встречи действует на новые запросы, ранее выданные токены не отзывает.

Опрос содержит 2–10 неповторяющихся вариантов и один изменяемый голос на сотрудника. При скрытых результатах участник видит только свой выбор до закрытия опроса. Модератор видит счётчики всегда. Список голосовавших другим участникам не выдаётся.

До 30 комнат обсуждений открываются по назначенным участникам. У каждой отдельные аудио, видео и демонстрация экрана. Чат, вопросы и опросы остаются общими для всей встречи. Запись основной комнаты не включает комнаты обсуждений. Возврат сохраняет выбранное состояние микрофона и камеры. Закрытие удаляет медиакомнату; если LiveKit недоступен, интерфейс показывает отсутствие подтверждения и позволяет повторить действие.

При завершении или отмене встречи приложение закрывает также все комнаты обсуждений и отключает основную медиакомнату. Если медиасервер не подтвердил операцию, PATCH вернёт 503 с объяснением: статус в БД уже сохранён, завершение нужно повторить. Завершённую встречу нельзя открыть повторно — создаётся новая встреча с новым ключом комнаты.

## Настройка LiveKit

Обновите конфигурацию работающего LiveKit, включая существующие установки:

```yaml
room:
  auto_create: false
webhook:
  api_key: YOUR_LIVEKIT_API_KEY
  urls:
    - https://work.company.ru/api/livekit/webhook
```

В Compose используется внутренний адрес `http://app:3000/api/livekit/webhook`; в Helm приведён пример для внешнего ingress. Адрес должен быть доступен с медиасервера, а `api_key` и соответствующий secret совпадать с приложением. Приложение создаёт комнаты серверным вызовом перед выдачей токена. `auto_create: false` не даёт старому JWT автоматически воссоздать закрытую комнату. Вход без такой конфигурации не обеспечивает это ограничение.

Журнал заполняется только подписанными событиями фактического подключения/выхода, а не запросами токенов. Повторы event.id не дублируются; порядок доставки не важен для пары join/leave. Одновременные интервалы одного сотрудника объединяются. LiveKit не гарантирует доставку всех событий: незавершённые интервалы показаны явно, время для них считается до момента запроса и может быть завышено. Это журнал участия, не табель оплаты труда. Без callback журнал пуст. История чата хранится независимо.

Основная комната на 1000 участников требует испытаний выбранного сервера, сети и числа выступающих. Комнаты обсуждений не означают, что одна большая встреча автоматически распределяется между SFU. HPA приложения не подтверждает вместимость встречи.

См. [официальную документацию webhook LiveKit](https://docs.livekit.io/intro/basics/rooms-participants-tracks/webhooks-events/) и [пример конфигурации сервера](https://github.com/livekit/livekit/blob/master/config-sample.yaml). Методы доступны в «Мой API» и `/api/openapi.json`.

## Субтитры

Три условия включения: администратор разрешает живые субтитры в настройках речи, организатор разрешает их во встрече, сотрудник с `conference.caption` сам включает распознавание своего включённого микрофона. Право настраивается у проектных ролей и групп; обычным участникам по умолчанию не выдано. Автоматически подключать распознавание микрофонов всех участников нельзя.

Панель CC показывает сохранённый текст. Обрабатывается только локальная аудиодорожка основной комнаты. При выключении микрофона, переходе в комнату обсуждения, сворачивании приложения или ошибке распознавание прекращается; возобновление явное. На телефоне работа в фоне не гарантируется. Чужая речь, попавшая в физический микрофон, также может попасть в распознавание; используйте наушники.

Браузер формирует самостоятельные аудиофайлы примерно по 8 секунд, максимум два ожидающих фрагмента. Сервер декодирует их ffmpeg, проверяет реальную длину 0,15–12 секунд и передаёт WAV настроенному `/audio/transcriptions` с таймаутом 30 секунд. У сервиса должно быть достаточно скорости для такой частоты; задержка включает длительность фрагмента, очередь и обработку. Паузы между фрагментами и границы слов могут ухудшать текст. Это не гарантированные субтитры без задержки и не полная запись встречи.

Исходное аудио субтитров не записывается приложением на диск или в S3. Провайдер получает его по своим настройкам хранения. Распознанный текст, автор, серверное время и длительность сохраняются в MySQL. Запись встречи в S3 остаётся отдельной, опциональной функцией. ИИ-изложение полной встречи по-прежнему использует подготовленную расшифровку записи, а не неполные субтитры.

Лимиты по умолчанию: 60 минут на сотрудника, 600 минут на пространство за UTC-сутки, 10 одновременных запросов распознавания. Новый запрос резервирует 12 секунд; успешный — фактическую длительность с округлением вверх. Ошибка сохраняет резерв для защиты от повторного расходования ресурсов. Не чаще одного запроса на сотрудника за 6 секунд. Лимит одновременности относится к запросам STT, а не к числу присутствующих во встрече. Для 1000 зрителей выбирайте небольшое число выступающих и проверяйте нагрузку.

Повтор `client_id` возвращает уже сохранённый текст без новой генерации, если аудио совпадает. Последовательность выдачи назначается по готовности текста: поздний ответ сервиса не потеряется за более быстрым. API позволяет постранично получить всю историю, интерфейс показывает последние 300 фрагментов (первоначально до 200).

Используются стандартные [MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder) и [копия собственной аудиодорожки](https://developer.mozilla.org/en-US/docs/Web/API/MediaStreamTrack/clone). Проверка реальных браузеров, мобильного фона и задержки STT остаётся обязательной перед эксплуатацией.
