# Контур Work 0.14.1

Исправление остановки обновления на `021_integrations.sql` с `ER_TABLE_EXISTS_ERROR`. Все возможности 0.14.0 сохранены; новых SQL-миграций нет, файлы 001–029 не изменены.

## Что исправлено

- Безопасное продолжение исходной 021 после частичного CREATE TABLE или потери финальной записи журнала. Проверяются обе таблицы, ограничения, индексы и родительские ключи. Совпадающие таблицы сохраняются, создаются только недостающие; строки не переписываются.
- Несовместимая схема останавливает восстановление до DDL. Проверка SHA-256 и порядка миграций сохраняется. Неизвестные незавершённые миграции по-прежнему блокируются.
- В `npm run db:status` появился блок `recovery_021`: существующие и недостающие таблицы, конфликты схемы. Диагностика читает только метаданные и журналы.
- В Compose/Helm используется тот же исправленный мигратор. Обновлены версия приложения, OpenAPI и chart.

## Установка исправления

Порядок обновления Compose и Kubernetes и разбор конфликтов — в [DATABASE-UPGRADES.md](DATABASE-UPGRADES.md#ошибка-021_integrationssql-прервана-er_table_exists_error). Не удаляйте таблицы или журнал миграций для обхода ошибки. Сохраните прежние окружение, имя Compose-проекта и тома.

Архив содержит исходники для сборки. Образ 0.14.1 нужно собрать и при использовании Kubernetes загрузить в свой registry. Этот выпуск не обновляет пользовательский сервер автоматически.

## Проверки

Добавлены тесты всех границ прерывания 021, повторного обрыва, различий схемы, защиты журналов, итоговой сверки и диагностики без записей. Регрессионные тесты 013 и общего мигратора остаются в наборе.

Итог: **189 тестов прошли**, включая 29 тестов мигратора и восстановления 013/021. Проверка CSS/PWA/UI-контрактов и production-сборка Next.js завершились успешно. Полный набор запускался последовательно командой `node --experimental-vm-modules --test --test-concurrency=1 --test-reporter=tap scripts/*.test.mjs`.

Изолированный `deploy/tests/mysql-recovery.compose.yaml` дополнен настоящим `ER_TABLE_EXISTS_ERROR`, проверкой сохранности подключения/доставки и восстановлением полностью созданных таблиц без финального маркера. Docker/MySQL в среде подготовки отсутствуют: сценарий включён, но здесь не запускался. Перед production-обновлением прогоните его и проверьте миграцию на копии своей БД.
