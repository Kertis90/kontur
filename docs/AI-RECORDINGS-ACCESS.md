# ИИ, записи встреч и доступ к проектам — 0.9.0

## Работа с записью встречи

1. Войдите в конференцию. В верхней панели откройте **Записи встречи → Начать запись сейчас**. Запись необязательна и сама при планировании не запускается.
2. Участникам показывается индикатор записи. **Остановить запись** запускает сохранение MP4 в приватный S3. Закрытие браузера ведущего не останавливает серверную запись; завершение самой конференции останавливает её.
3. После статуса **Сохранено в S3** доступны просмотр и скачивание MP4. Перемотка использует HTTP Range; приложение проверяет доступ при каждом запросе файла. Прямой публичный адрес S3 не выдаётся.
4. Нажмите **Расшифровать аудио**. Отдельный worker извлечёт речь и отправит десятиминутные фрагменты в настроенный сервис распознавания. Прогресс и ошибки показаны рядом с записью.
5. После готовности нажмите **Изложить встречу с ИИ**. Выберите модель и при необходимости укажите, на чём сосредоточиться. Изложение содержит содержание встречи, решения, поручения, открытые вопросы и следующие шаги, если эти сведения есть в источнике.

В карточке конференции тоже есть **Записи встречи**, включая завершённые встречи. Без записи можно сформировать отдельную сводку чата и вопросов через **Сводка с ИИ**. Источник всегда явно указан. Чат хранится в MySQL и экспортируется отдельно; MP4 не содержит текстовый архив чата.

Изложение записи основано на аудиодорожке. Оно не распознаёт текст с демонстрируемого экрана и не анализирует изображение. Расшифровка может ошибаться и не устанавливает личность говорящего. Время в TXT обозначает начало десятиминутного фрагмента, а не точное время каждой реплики. Проверяйте решения и имена перед использованием результата.

Готовая расшифровка хранится в MySQL и общая для всех пользователей с доступом. Повторная обработка готовой записи не отправляет аудио провайдеру. После ошибки уже обработанные фрагменты используются повторно, если настройки распознавания не изменились. Готовая расшифровка при изменении модели автоматически не заменяется.

## Настройка ИИ и распознавания

Откройте **Администрирование → Искусственный интеллект**. Нужно право `ai.configure`; персональным API-токенам этот раздел недоступен.

- Создайте профиль: название, базовый URL, протокол, ключ и точное имя модели. Можно иметь до 20 подключений к разным серверам.
- Для загрузки списка моделей сохраните URL, нажмите **Загрузить модели**, выберите модель и сохраните снова. Сервер без `/models` поддерживается: имя вводится вручную.
- Выберите профили по умолчанию для оценки проектов и сводок конференций. Включите ИИ для рабочего пространства.
- Задайте лимит запусков на пользователя в сутки, размер входного контекста, лимит ответа, таймаут и дополнительные правила. `temperature` необязательна: пустое значение не отправляется модели.
- В **Распознавание аудиозаписей встреч** задайте отдельный базовый URL, модель, язык и при необходимости ключ. Включите распознавание. Этот переключатель независим от генерации текста.

Базовый URL, например `https://llm.company.ru/v1`, указывается без конечного метода. Генерация поддерживает `/chat/completions` и `/responses`, список моделей — `/models`. В режиме Chat Completions можно выбрать параметр `max_tokens` или `max_completion_tokens`. Совместимость зависит от методов конкретного сервера: [контракт Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create/), [совместимые методы Ollama](https://docs.ollama.com/api/openai-compatibility).

Распознавание использует `POST {base_url}/audio/transcriptions`, multipart-поля `file`, `model`, `language`, `response_format=json`; ожидается JSON `{ "text": "..." }`. Этот профиль используется для записей встреч. Старые `STT_API_URL`, `STT_API_KEY`, `STT_MODEL` продолжают обслуживать голосовые комментарии задач.

Ключи шифруются с `APP_ENCRYPTION_KEY`; браузер получает только признак сохранённого ключа. Пустое поле сохраняет ключ, отдельный флажок удаляет его. Сохраняйте ключ шифрования при переносе инсталляции. URL должен быть доступен приложению и worker; внутренние HTTP-серверы допустимы, редиректы не разрешены. Ограничивайте исходящий трафик к доверенным провайдерам на уровне своей сети.

Анализ запускается в очереди `kontur-ai`, отдельно от уведомлений. Повтор одинакового запроса по неизменным данным использует сохранённый результат. **Сформировать заново** выполняет новую генерацию. Не более трёх незавершённых запросов на пользователя; суточный лимит считается по UTC. Контекст задачи удаляется из очереди после завершения; результат и метаданные остаются.

Длинная аудиозапись обрабатывается по частям, затем промежуточные итоги объединяются. Проектные задачи и чат ограничены выбранным размером контекста: интерфейс показывает, сколько записей вошло, и предупреждает о неполной выборке. Для слишком маленького контекста длинной записи возвращается явная ошибка с предложением увеличить лимит. Одна длинная встреча может потребовать несколько оплачиваемых запросов провайдера.

## Доступ пользователей и групп

**Администрирование → Роли и группы → Группы** позволяет создавать группы, искать сотрудников и выбирать их флажками. Вложенные группы и временные назначения продолжают учитываться.

В **Проекты → Настройки и доступ → Пользователи и группы**:

- назначьте пользователю или группе роль руководителя, участника или наблюдателя;
- измените либо удалите конкретное назначение;
- выберите сотрудника в **Проверить фактические права** и просмотрите итоговые разрешения.

Управляющий доступом может выдавать только роли, все разрешения которых есть у него самого. Последнего прямого руководителя нельзя удалить или понизить, пока не назначен другой. Удаление одного назначения не отменяет другие источники доступа. Владелец и системный администратор сохраняют полный доступ ко всем существующим проектам своего пространства.

| Разрешение | Что открывает |
|---|---|
| `project.create` | Создание новых проектов; право рабочего пространства |
| `project.edit` | Изменение параметров проекта |
| `project.archive` | Архивирование и возврат в работу |
| `project.delete` | Корзина и восстановление |
| `project.access.manage` | Прямые и групповые назначения, проверка прав |
| `conference.record` | Запуск и остановка записи |
| `conference.recording.view` | Просмотр видео, расшифровки и основанных на ней результатов |
| `ai.project.analyze` | Запуск оценки проекта |
| `ai.conference.summarize` | Запуск расшифровки и изложения встречи |
| `ai.result.view` | Просмотр результатов ИИ без права генерации |
| `ai.configure` | Управление серверами, моделями и лимитами; право рабочего пространства |

Руководитель проекта получает все проектные разрешения. Участнику и наблюдателю запись и ИИ автоматически не выдаются: добавьте нужные разрешения через функциональную роль. Для записи и ИИ дополнительно проверяется доступ к конкретной конференции. Просмотр изложения по записи требует и права на результат ИИ, и права на запись.

Права суммируются из прямого членства, групп, схем и назначений ролей; явный запрет перекрывает разрешение. Явный запрет `project.browse` закрывает проектные действия. `project.admin` сохраняет совместимость со старыми назначениями и даёт новые действия управления проектом; адресный запрет конкретного действия сохраняет приоритет.

Архив скрывает проект из активного портфеля. Корзина закрывает проект и его записи для обычной работы, отменяет незавершённые запросы ИИ и инициирует остановку активной записи через worker. Восстановление доступно из **Проекты → Корзина**. Это обратимое удаление; физическая очистка проекта и S3-файлов в этой версии не выполняется автоматически.

## API

Новые методы включены во встроенную документацию **Мой API** и OpenAPI. Полные примеры находятся также в [API.md](API.md).

`ai:read` и `ai:write` включаются администратором в политике пользователя и выбираются при выпуске токена. Они не входят в стандартный набор новых токенов. Пользовательские разрешения проверяются дополнительно. Фоновый worker повторно проверяет роль, активность пользователя, отзыв токена и политику перед обращением к модели. Уже отправленный провайдеру запрос отозвать нельзя.

Настройки ИИ доступны только через сессию администратора: `GET/PUT /api/admin/ai`, `POST /api/admin/ai/profiles/{uuid}/models`, `POST /api/admin/ai/profiles/{uuid}/test`. PUT принимает `enabled`, `daily_user_limit`, `profiles`, `project_profile_id`, `conference_profile_id`, `speech`. GET возвращает текущую структуру без ключей; её можно изменить и отправить обратно. Проверка генерации делает короткий реальный запрос модели.

## Компоненты и эксплуатация

Compose запускает `egress` и `recording-worker` вместе с приложением. `RECORDING_ENABLED=false` запрещает новые записи, но оставляет доступ к сохранённым. `LIVEKIT_EGRESS_IMAGE` задаёт образ Egress. Значение `latest` в примере предназначено для первоначальной установки; перед production закрепите проверенный образ по digest и проведите проверку совместимости.

Для Helm используются `recordings.enabled`, `recordings.egress.replicas`, `recordings.egress.image`, `recordings.workerReplicas`. При внешнем Secret добавьте ключ `EGRESS_CONFIG_BODY` по [примеру Egress](../deploy/helm/kontur-work/egress-production.example.yaml). Egress должен использовать те же Redis и ключи LiveKit, иметь доступ к RTC-портам media-узлов и к S3. Worker нужен доступ к MySQL, Redis, S3, STT и ИИ.

Egress разворачивается отдельным сервисом. В манифестах выделены 4 CPU и 4 GiB на экземпляр; количество реплик планируется по числу одновременно записываемых комнат. Эти ориентиры и требования Chrome описаны в [документации LiveKit Egress](https://docs.livekit.io/transport/self-hosting/egress/). Только контейнер Egress получает `SYS_ADMIN` для Chrome sandbox; Pod Security вашей инфраструктуры должен разрешать эту настройку в выбранном namespace.

Расшифровка ограничена 12 часами и размером `RECORDING_TRANSCRIBE_MAX_GB` (по умолчанию 20 ГБ). Файл скачивается потоково во временный каталог worker, затем обрабатывается ffmpeg; целая видеозапись не загружается в память. Предусмотрите место под исходный файл и аудиофрагменты: в Helm 24 GiB временного диска на worker при concurrency=1. При увеличении параллельности увеличьте диск пропорционально. После штатного завершения или ошибки временные файлы удаляются; после аварийного SIGKILL контейнер Compose может требовать очистки временного слоя или пересоздания.

Egress и запись не делят одну комнату на несколько media-узлов. Встреча около 1000 зрителей требует вебинарного режима, подходящего media-узла и нагрузочной репетиции. Падение узла во время записи не обеспечивает бесшовного продолжения: возможна потеря незавершённого файла; PDB и graceful termination уменьшают риск при плановых работах, но не заменяют проверку отказов.

Политики хранения, шифрование S3 на стороне сервера, lifecycle и резервные копии задаются инфраструктурой. Не удаляйте объекты через S3 lifecycle раньше согласованного срока доступности записей в приложении. MySQL хранит связь с файлом, расшифровку и итог ИИ: резервируйте его вместе с S3.
