# Контур Work 0.17.0 · расширенный конструктор ИИ

## Возможности

- Визуальный редактор до 16 шагов: анализ разными моделями, условия с ветками, фильтрация источников, текстовые шаблоны и раннее завершение. Типизированные результаты шагов и до 12 входных параметров.
- Ежедневные/недельные расписания с часовым поясом, интервал, события комментариев, условия до вызова модели, настраиваемая очередь и пауза между автоматическими запусками.
- Новые источники: пользовательские атрибуты с ACL, открытые комментарии и чек-листы задач, чаты, готовые расшифровки записей встреч, спринты/релизы, цели и выборка статей пространств.
- Восемь типов действий: задачи, комментарии, изменение полей, этапы, исполнители, чек-листы, черновики статей, сообщения в разрешённые чаты. Проверки прав, версий и согласований сохранены.
- Тестовый запуск с моделью без применения действий, в том числе у выключенных агентов. Предпросмотр источников по-прежнему не вызывает модель.
- Проверки уверенности, ссылок и обоснований. Не прошедшие их автоматические предложения требуют подтверждения. Опциональное скрытие email в источниках.
- История и восстановление конфигураций, копирование, импорт/экспорт JSON, шесть шаблонов.
- Журнал каждого шага и итогового вызова, фильтр статусов, JSON-экспорт результата, индивидуальные оценки, статистика за выбранный период.
- Русский адаптивный интерфейс, документация новых API в «Мой API» и OpenAPI, [руководство](AI-AGENTS.md) и [пример агента](../examples/agents/reviewed-project.json).

Граф выполняет только заданные типы шагов и разрешённые операции. Произвольные скрипты, анонимные webhook, циклы графа, автоматическое обучение модели и автоматическая транскрипция записей в конструкторе не добавлены. Для записей используются уже готовые расшифровки. Подробные границы выборок и метрик приведены в руководстве.

## Совместимость и обновление

Миграция **033_agent_studio.sql** добавляет четыре таблицы: `ai_agent_versions`, `ai_agent_run_state`, `ai_agent_run_steps`, `ai_agent_run_feedback`. Все файлы 001–032 и механизмы восстановления 013/021 оставлены без изменений. Существующие конфигурации дополняются безопасными значениями при чтении; новые действия не включаются автоматически. Старые результаты и запуски поддерживаются без обязательного заполнения новых таблиц задним числом. История старого агента начинает фиксироваться при следующем изменении или паузе.

Новых зависимостей, контейнеров или обязательных переменных окружения нет. Нужны обновлённые app/worker, MySQL и настроенный профиль ИИ. Compose и Helm используют прежние компоненты; версия chart/image — 0.17.0. БД и процессы должны работать в UTC, локальные расписания хранят свой IANA timezone в конфигурации.

Сохраните проверенную резервную копию БД и прежние настройки/секреты. На время обновления остановите запись старых процессов. В каталоге существующего Compose-проекта (с прежним `-p`, если используется) выполните последовательно:

```sh
docker compose stop app worker recording-worker
docker compose build migrate
docker compose run --rm --no-deps --entrypoint node migrate scripts/migrate.mjs --status
docker compose run --rm --no-deps --entrypoint node migrate scripts/migrate.mjs
docker compose up -d --wait
```

Продолжайте после успешного завершения каждого шага. Общий образ собирается через `build migrate`; при собственных override с разными образами обновите каждый. Не создавайте новый Compose-проект с пустыми томами и не выполняйте `down -v`.

В Kubernetes соберите/загрузите образ 0.17.0, обновите chart с существующими values/секретами. Перед миграцией приостановите старые app/worker: pre-upgrade hook не делает этого автоматически. Не запускайте старые worker одновременно с миграцией.

При частичном выполнении 033 повтор блокируется общим мигратором: DDL MySQL не откатывается транзакцией целиком. Сначала `--status`, затем сверка фактической схемы на копии по [DATABASE-UPGRADES.md](DATABASE-UPGRADES.md). Не удаляйте журнал и не меняйте SQL для обхода проверки. Специального автоматического восстановления 033 нет. Откат приложения после применения миграции требует согласованного восстановления БД и кода из резервной копии.

После обновления проверьте выключенного агента кнопкой «Тест», права источников, историю после редактирования и расписание в нужном поясе. Для рабочего вызова ИИ в сценарии с двумя аналитическими шагами требуется бюджет на три обращения: два шага плюс итог.

## Проверки

- **253 серверных теста в 26 файлах**: прежняя функциональность и 21 новый тест студии, включая ветвления, типы данных, DST, права источников/действий, идемпотентность, тестовый режим, контроль качества, очередь, восстановление версий и API scopes.
- Production-сборка Next.js, проверка стилей/PWA/API-контрактов, разбор YAML Compose/Chart/values.
- Серверный рендер шести панелей редактора, всех пяти типов шагов и недельного расписания. Проверка валидности импортируемого примера.
- Побайтовая проверка неизменности всех 32 прежних SQL-миграций.

Среда не содержит MySQL, Docker, Helm CLI и установленного Chromium. Миграция на живой БД, контейнерное развёртывание и браузерная проверка адаптивной вёрстки не выполнены. Серверные обращения к ИИ проверены с подставными ответами провайдера; реальных запросов к вашей модели и сообщений сотрудникам не отправляли. Архив готов для self-hosted установки, работающий сервер автоматически не обновлён.
