# Контур Work 0.10.0

Расширение планирования, совместной работы и результатов встреч.

## В этой версии

- Визуальный конструктор автоматизаций: условия, ветви, расписание, пробный запуск и журнал.
- Последовательные и параллельные согласования, заместители, напоминания и защищённые переходы задач.
- Загрузка команд, рабочие графики, отпуска, распределение часов между проектами.
- Межпроектные зависимости, критический путь, сценарии сроков и базовые планы.
- Проверяемые поручения ИИ из расшифровки встречи с созданием задач по подтверждению.
- Главы и поиск по записи, исправления расшифровки, история и срок хранения S3-файла.
- Поиск с ИИ по доступным задачам, статьям и записям со ссылками на источники.
- Совместная работа с блоками статей, комментарии, версии, ответственные и проверка актуальности.
- Доступ пользователей и групп к пользовательским полям, временные запросы доступа и объяснение полномочий.
- Офлайн-черновики задач и комментариев, голосовые записи и разрешение конфликтов синхронизации.
- Импорт Jira/CSV с проверкой, массовое изменение задач, GitHub/GitLab webhooks и описания релизов.
- Личные почтовые настройки, тихие часы и дайджесты.
- Каталог API, адаптивные формы и защита интерфейса от устаревших ответов при переключении разделов.

Сценарии, границы возможностей и разрешения описаны в [руководстве](WORK-MANAGEMENT.md).

## Обновление с 0.9.0

Миграция `012_work_management.sql` добавляет новые таблицы и индексы. В существующих проектах ограничения полей и согласований по умолчанию отсутствуют, офлайн и личная почта выключены. У существующих записей срок хранения остаётся неограниченным.

1. Сохраните резервную копию MySQL, S3 и ключ шифрования. Проверьте восстановление на своей инфраструктуре.
2. Соберите образ версии `0.10.0`. Обновите образ приложения, обычного worker, worker расшифровки и задания миграции вместе.
3. Выполните штатное обновление Compose либо Helm: миграция должна завершиться до переключения приложения.
4. Откройте новые разделы под администратором, настройте функциональные роли и при необходимости новые API scopes.
5. Проверьте старые автоматизации пробным запуском. Затем создайте тестовый запрос согласования, конфликт двух правок и короткую запись встречи.

Для Compose используется существующий комплект с MySQL, Redis, MinIO/S3, LiveKit и Egress:

```bash
docker compose up -d --build --wait
docker compose ps
docker compose logs --tail=100 migrate app worker recording-worker
```

В chart обновлены `version`, `appVersion` и стандартный `image.tag` до `0.10.0`. Сначала опубликуйте собственный образ в доступный кластеру registry, затем примените chart с вашими values и секретами. Подробная схема установки остаётся в [README](../README.md).

Новая необязательная настройка:

| Где | Параметр | Значение |
| --- | --- | --- |
| Compose / окружение | `RECORDING_RETENTION_DAYS` | `0` — без автоудаления, положительное целое — дней хранения новых записей |
| Helm | `recordings.retentionDays` | То же значение |

Срок конкретной записи меняется в её интерфейсе. Периодические задания обычного worker выполняют расписания, напоминания, личную почту и удаление просроченных записей. Дополнительный сервис для этой версии не требуется. Для поручений используется очередь ИИ; для подготовки расшифровки — отдельный worker записей.

Возврат только образа 0.9.0 после настройки новых ограничений доступа небезопасен: старое приложение не учитывает политики полей и согласования. Для отката нужен согласованный возврат кода и данных из резервной копии.

## Проверки и границы готовности

Выполнены production-сборка Next.js, статическая проверка CSS/PWA/API/deployment-файлов и 50 автоматических проверок поведения. YAML Compose, values и Chart проверены парсером; это не заменяет запуск Helm. Тесты покрывают закрытую историю конференций, права и запреты, API-политики, кэш ИИ, запись, HTTP Range, обработку ffmpeg, ветвление правил, расчёты планирования, версии согласований, редактирование блоков, скрытые атрибуты, повторы офлайн-запросов, CSV/Jira и подписи webhook.

Эта версия подготовлена как исходный код и комплект развёртывания. В данной среде нет работающей инфраструктуры платформы: миграции не выполнялись на реальном MySQL, Compose и Helm не запускались, внешние SMTP/S3/LiveKit/ИИ/webhook интеграции не проходили сквозной тест. Браузерная проверка нового интерфейса не выполнена. Нагрузочный тест встречи на 1000 участников не проводился; для такого масштаба нужен отдельный стенд и проверка SFU, Egress, сети и клиентских устройств. Увеличение числа реплик приложения само по себе не подтверждает эту ёмкость.
