# Контур Work 0.23.1 — прокси и закрытый реестр

Выпуск дополняет установку для сети с собственными репозиториями пакетов
и HTTP/HTTPS-прокси. Продуктовые предложения сохранены отдельно в
[NEXT-IMPROVEMENTS.md](NEXT-IMPROVEMENTS.md) и не реализованы без выбора владельца.

## Изменения

- Compose передаёт `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, `ALL_PROXY` при сборке
  приложения и хранилища. Готовое приложение не получает эти параметры окружения.
- Можно заменить образы MySQL, PostgreSQL, Redis, LiveKit и Caddy через `.env`.
  Проверки восстановления используют тот же адрес образа выбранной БД.
- Обработчик Dockerfile хранилища можно получать из внутреннего реестра через
  `BUILDKIT_SYNTAX`; источники npm/apk/apt/Go и архивов сохранены.
- Общий `imagePullSecrets` Helm теперь передаётся также LiveKit и записи встреч.
  Добавлен `values-private.example.yaml` со всеми образами chart.
- Исправлены устаревшие теги приложения в примерах Helm; HA-пример берёт версию
  из chart. Дополнены `.env`-примеры, README и [руководство сети](BUILD-SOURCES.md).
- Локальный `.env` дополнен только отсутствующими закомментированными примерами.
  Действующие адреса, секреты и выбранная БД сохранены.

## Проверки

- На Node.js 22 прошли 342 серверных теста, `npm run quality` и production build.
- Compose проверен с настройками по умолчанию и с тестовыми внутренними адресами
  для MySQL и PostgreSQL, включая отдельные конфигурации восстановления.
  Прокси попадает только в аргументы сборки, не в окружение запущенных сервисов.
- Строгий Helm lint и разбор готовых манифестов прошли для обеих БД с обычными
  и закрытыми реестрами. Проверены восемь типов pod в каждом варианте, включая
  миграцию, резервирование и `helm test`; все получают общий `imagePullSecrets`.
- Через одноразовое зеркало и HTTP-прокси собран полный образ приложения
  `kontur-work:0.23.1`, стадия `runtime` хранилища и выполнено реальное скачивание
  модуля Go с проверкой суммы. Подтверждены обращения npm (143), apk (107),
  apt (24), Go (4), всего 278 запросов через HTTP-прокси и два HTTPS-туннеля.
  В окружении и истории трёх образов нет стандартных параметров HTTP-прокси.
  Адреса обычных зеркал остаются аргументами сборки, поэтому они не должны
  содержать секретов.
- SHA-256 образа приложения:
  `65682516c47e4942c52834834687b395cf8a4bf72bd1ddb70e721de76479b951`.
  Образ создан локально; в реестр контейнеров он не публиковался.
- `git diff --check` и строгая проверка UTF-8 прошли. Выпущенные миграции не менялись.

Одноразовый прокси удалён после проверки. Подробные журналы находятся в TEMP,
а не в репозитории. Полная повторная сборка бинарников MinIO и `mc` в этой правке
не требовалась: их Dockerfile не менялся, проверена затронутая сетевая настройка
для apt и Go. Интерфейс не менялся, отдельный локальный браузерный прогон не повторялся.
Настоящий Kubernetes и корпоративные адреса здесь не запускались.

## Обновление

Новые параметры необязательны, прежние адреса по умолчанию сохранены. Для работы
в своей сети укажите реальные адреса, подготовьте доступ к реестру и сертификаты
по [BUILD-SOURCES.md](BUILD-SOURCES.md). Новых миграций нет: MySQL 001–044 и
PostgreSQL 001–003 остаются неизменными.

Настройки узлов Kubernetes, рабочего Docker и рабочих БД не менялись. Тестовая
проверка не подтверждает доступ к корпоративным зеркалам, которых нет в этой среде.
