## Обновление

Добавлены только новые миграции `031_allure.sql` и `032_ai_agents.sql` (по две таблицы). Файлы 001–030 и восстановление 013/021 не изменены. Все существующие роли/назначения сохраняются; новые разрешения доступны в редакторе ролей. API scopes агента не добавляются к токенам по умолчанию.

Новых контейнеров или обязательных переменных окружения нет: нужны обновлённые `app` и `worker`, доступ к MySQL и настроенному вами endpoint ИИ. Compose и Helm используют существующий worker; несколько реплик не забирают один запуск одновременно.

Перед обновлением сохраните проверенную резервную копию БД, секреты и конфигурацию. Остановите новые запросы/записи на время миграции. Команды для существующего Compose-проекта из его каталога (с прежним `-p`, если используете):

```sh
docker compose stop app worker recording-worker
docker compose build migrate
docker compose run --rm --no-deps --entrypoint node migrate scripts/migrate.mjs --status
docker compose run --rm --no-deps --entrypoint node migrate scripts/migrate.mjs
docker compose up -d --wait
```

Выполняйте следующий шаг после успешного завершения предыдущего. `build migrate` собирает общий образ; если override использует отдельные образы для разных служб, обновите каждый. Не создавайте новый Compose-проект с пустыми томами и не выполняйте `down -v`.

В Kubernetes соберите образ `0.16.0`, загрузите его в свой registry и обновите chart/values, сохранив секреты и параметры. Перед миграцией приостановите запись старых app/worker: pre-upgrade hook не останавливает их автоматически. Образ и chart этой версии содержат всё необходимое для агентов, дополнительного сервиса нет.

Если новая миграция прервана, MySQL DDL мог сохраниться частично. Не удаляйте журнал и не редактируйте старые SQL: снимите `--status`, сверяйте схему с файлами на восстановленной копии БД по [DATABASE-UPGRADES.md](DATABASE-UPGRADES.md). Для 031/032 слепой автоматический повтор заблокирован общим мигратором; специальных исключений восстановления не добавлено.

После обновления: создайте подключение Allure, импортируйте небольшой реальный прогон, подключите профиль ИИ, создайте выключенного агента, проверьте выборку и выполните ручной запуск. При необходимости назначьте новые права и включите нужные триггеры.

## Проверки и границы проверки

Пройдены **232 автоматических теста в 25 файлах**, включая Allure, права источников, защиту от повторного применения, отмену генерации, scopes токенов и обработку ответов модели. Проверены production-сборка Next.js, стили, PWA/API-контракты, YAML Compose/Helm и неизменность старых миграций.

В среде разработки отсутствуют MySQL, Docker и Helm CLI; миграции не запускались на живой БД и контейнеры не разворачивались. Рабочие endpoint ИИ/Allure не подключены. Реальная генерация, отправка из CI и визуальная проверка в браузере на вашей установке не проводились. Серверные сценарии ИИ проверены с подставными ответами провайдера. Архив содержит обновление для вашей self-hosted установки; её работающий сервер автоматически не обновлён.
