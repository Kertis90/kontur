# Чат, приложение и уведомления

## Чат рядом с работой

Кнопка справа открывает панель чата поверх текущего раздела. На экранах от 1600 px открытая панель получает отдельную полосу и сдвигает содержимое; на более узких экранах её можно свернуть. На телефоне кнопка находится над нижней навигацией. Панель учитывает safe area, доступную высоту экрана и экранную клавиатуру. В полном разделе «Чат и встречи» кнопка справа открывает настройки устройства.

В панели доступны поиск по названиям и проектам, счётчики непрочитанных, переписка, загрузка файлов до 25 МБ и переход в полный чат. Более низкий серверный `MAX_ATTACHMENT_BYTES` продолжает применяться. Черновики панели сохраняются в памяти при переключении чатов и разделов, но не после перезагрузки страницы или выхода. Отправка требует сети; сообщения не ставятся в скрытую офлайн-очередь. При ошибке текст остаётся в поле.

По умолчанию загружаются последние 100 сообщений. «Предыдущие сообщения» подгружает историю, а новые записи добавляются без потери уже открытых страниц. Уведомления о непрочитанном не включают собственные и удалённые сообщения. Интерфейс подтверждает прочтение, когда чат открыт, вкладка видима и пользователь находится внизу истории. Закрытая панель, раздел конференций и фоновая вкладка не подтверждают прочтение. Состояние синхронизируется через сервер: новые сообщения проверяются раз в 4 секунды, списки чатов и счётчики — раз в 15 секунд. Браузер может замедлять таймеры фоновой вкладки.

## Установка PWA

Откройте ⚙ «Приложение и уведомления» справа. Если браузер предлагает установку, появится кнопка «Установить Контур». В иных случаях воспользуйтесь меню браузера. Для iPhone/iPad: Safari → «Поделиться» → «На экран Домой», затем откройте установленное приложение. Web Push для веб-приложений на домашнем экране поддерживается начиная с iOS/iPadOS 16.4: [документация WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).

Для PWA и уведомлений нужен HTTPS (localhost допускается для разработки). При открытии сайта запрос разрешения не показывается: пользователь нажимает «Включить уведомления» сам. Если разрешение отклонено, повторно разрешить его нужно в настройках сайта браузера. [Правила Notifications API](https://developer.mozilla.org/en-US/docs/Web/API/Notifications_API/Using_the_Notifications_API).

Service worker кэширует только оболочку, manifest, иконки и публичные сборочные файлы. API, загрузки и приватные документы в этот кэш не попадают. Отсутствующий JS/CSS-файл не заменяется HTML. Без сети возможности изменения данных и чата ограничены; существующий раздел офлайн-работы использует отдельное хранилище.

## Два режима уведомлений

- **При открытом приложении.** Работает после согласия пользователя, даже если серверный push ещё не настроен. Проверяются новые сообщения и уведомления текущего пользователя; системное уведомление появляется, когда вкладка скрыта. При закрытой вкладке этот режим не работает.
- **Фоновые Web Push.** Требует настройки ниже. Worker доставляет уведомления через push-службу браузера; открытая вкладка не требуется. Доставка зависит от подключения устройства, браузера и настроек ОС. Это не механизм гарантированной мгновенной доставки: при большом числе устройств очередь может задерживаться.

Уведомление содержит только «Есть новые сообщения или уведомления», без текста чата, названий задач, файлов и секретов. Клик открывает соответствующий чат либо центр уведомлений. Счётчик на иконке приложения используется там, где браузер поддерживает Badging API.

Фоновые уведомления охватывают сообщения доступных чатов и сохранённые уведомления задач, встреч, статей и согласований, проверяя права заново. Чат конференции использует отдельный механизм комнаты; Web Push этой версии не рассылает каждое сообщение конференции. Тихие часы из личных настроек учитываются серверным worker; настройки почтового дайджеста не меняют доставку чатов.

Подписка привязана к браузерной сессии, хранится зашифрованной, ограничена десятью устройствами пользователя. API-токеном её создать нельзя. Выход удаляет подписку текущей сессии, закрывает показанные уведомления и сбрасывает значок приложения. При истечении/отзыве сессии либо блокировке пользователя worker удалит неактивную подписку. Уже доставленное ОС уведомление невозможно отозвать с сервера; в нём нет текста переписки. Отключение на одном устройстве не отключает остальные.

## Настройка Docker Compose

1. Обновите код и примените миграции до `030_browser_notifications.sql` по инструкции выпуска. Не меняйте старые файлы SQL.
2. Один раз создайте VAPID-ключи: `npm run push:keys`. При работе только через Docker: `docker compose run --rm --no-deps --entrypoint node app scripts/generate-web-push-keys.mjs` из каталога установки после сборки образа.
3. Сохраните пару ключей в защищённом окружении установки (не в Git):

```dotenv
WEB_PUSH_ENABLED=true
WEB_PUSH_PUBLIC_KEY=ПУБЛИЧНЫЙ_КЛЮЧ_ИЗ_КОМАНДЫ
WEB_PUSH_PRIVATE_KEY=ПРИВАТНЫЙ_КЛЮЧ_ИЗ_КОМАНДЫ
WEB_PUSH_SUBJECT=mailto:admin@your-company.ru
```

4. Выполните `docker compose up -d app worker`. В Compose переменные передаются обоим сервисам. Worker должен работать постоянно. После изменения окружения одного `restart` недостаточно.
5. Войдите через HTTPS и включите уведомления в настройках устройства. Проверьте доставку между двумя тестовыми пользователями в доступном им канале, затем повторите с закрытой вкладкой получателя.

Не меняйте VAPID-ключи при каждом запуске. Все реплики app/worker используют одну пару. После смены ключей пользователю потребуется отключить и заново включить уведомления на устройстве. `APP_ENCRYPTION_KEY`, как и прежде, должен быть сохранён при обновлениях.

## Настройка Kubernetes

```yaml
webPush:
  enabled: true
  publicKey: "ПУБЛИЧНЫЙ_КЛЮЧ"
  subject: "mailto:admin@your-company.ru"
secrets:
  existingSecret: kontur-production
```

Добавьте `WEB_PUSH_PRIVATE_KEY` в тот же существующий Secret, сохранив остальные требуемые ключи. Если chart создаёт Secret сам, используйте `webPush.privateKey` через защищённый файл values. Приватный ключ не входит в ConfigMap. Публичный ключ, subject и флаг доступны app и worker через ConfigMap. При внешнем Secret его обновление само по себе не перезапускает Pod: выполните обычное обновление Deployment/rollout.

Worker использует краткосрочную аренду подписки в MySQL и повторную проверку времени обработки при захвате, чтобы реплики не брали одно устройство одновременно. Ошибки 404/410 удаляют истёкшую подписку; временная ошибка переносит попытку на 5 минут, сохраняя курсоры событий. При аварии между отправкой и фиксацией результата возможна повторная доставка; одинаковый notification tag заменяет предыдущую карточку.

Нужен исходящий HTTPS-доступ worker к push-службам используемых браузеров: FCM (`fcm.googleapis.com`), Mozilla (`*.push.services.mozilla.com`), Apple (`web.push.apple.com`, поддомены) и Windows (`*.notify.windows.com`). Произвольные URL, HTTP, нестандартные порты и URL с логином/паролем не принимаются. Инфраструктура push-служб внешняя; для полностью изолированной сети используйте уведомления внутри открытого приложения. Не открывайте входящий доступ к MySQL или Redis ради уведомлений.

## API

Полный каталог и OpenAPI доступны в «Мой API» и `/api/openapi.json`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/chat/channels/{id}/messages` | Последние 100 сообщений; `after`/`before` для страниц, `mark_read=false` для просмотра без отметки |
| POST | `/api/chat/channels/{id}/read` | `{ "message_id": 123 }`; курсор может только увеличиваться |
| GET | `/api/work/push` | `configured`, `public_key`; только сессия браузера |
| POST | `/api/work/push` | `PushSubscription.toJSON()`; привязка устройства к сессии |
| DELETE | `/api/work/push` | `{ "endpoint": "…" }`; удалить собственную подписку |

`after=0` начинает историю с первого сообщения; без `after` открывается конец истории. `before` должен быть положительным, курсоры несовместимы. Старые API-клиенты по умолчанию сохраняют автоматическую отметку прочтения при GET. Новый интерфейс всегда передаёт `mark_read=false` и подтверждает фактически открытую переписку отдельным запросом.

## Проверка на стенде

Проверьте ширины 360/390, 768, 1280 и 1920 px: цели с длинными названиями, формы тест-кейсов, каталог/редактор интеграций, панель чата и её сворачивание. На телефоне откройте клавиатуру, отправьте многострочный текст и файл; кнопка отправки должна оставаться доступной. Переключите каналы во время загрузки, подгрузите старую историю и убедитесь, что новые сообщения не сбрасывают прокрутку. Проверьте два пользователя с разными правами, отзыв сессии, выключенный worker, запрет уведомлений и тихие часы.
