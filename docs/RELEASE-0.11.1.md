# Контур Work 0.11.1

Исправление блокирующей ошибки обновления `013_sessions_and_directory.sql` после 0.11.0. Само сообщение о незавершённой миграции вторично: первоначальную причину теперь можно увидеть через `npm run db:status`.

- Compose задаёт MySQL `log_bin_trust_function_creators=1`, необходимый для обычного пользователя миграций при включённом binlog без глобальных привилегий создания триггеров.
- Исходная миграция `013` получает проверяемое восстановление после частичного DDL: сверка схемы, создание только отсутствующих объектов, повторная проверка перед завершением журнала. Таблицы и данные не пересоздаются. Контрольная сумма исходного SQL сохранена.
- Другие незавершённые миграции по-прежнему блокируются; в сообщении показывается сохранённый код ошибки. Новые миграции с триггерами проверяют настройку MySQL до DDL.
- `node scripts/migrate.mjs --status` показывает состояние журналов, контрольных сумм, параметров binlog и объектов `013` без изменения БД.
- Обновлены общий образ/Helm version, инструкция восстановления и отдельный интеграционный сценарий с одноразовой MySQL 8.4.

Команды для существующей установки и внешней MySQL приведены в [DATABASE-UPGRADES.md](DATABASE-UPGRADES.md). В Compose сохраняйте прежние `.env`, имя проекта и тома. Не удаляйте маркер ошибки или том MySQL для обхода сбоя.

API-методы не менялись: опубликованный контракт 0.11.0 остаётся справочником методов, текущий `/api/openapi.json` сообщает версию 0.11.1.

Локально прошли полный набор из 136 тестов, затем три дополнительные проверки завершения журнала, исходного кода ошибки и предварительного отказа до `014` (всего 139 тестов, из них 19 для мигратора/восстановления). Производственная сборка, проверка качества и разбор YAML также прошли. Docker/MySQL/Helm в среде подготовки недоступны, поэтому интеграционный сценарий на MySQL 8.4 здесь не запускался. Обновление на сервер пользователя автоматически не устанавливалось.
