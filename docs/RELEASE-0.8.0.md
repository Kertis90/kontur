# Контур Work 0.8.0

## Изменения

- Исправлен выбор спринта в строке задачи: отсутствие story points больше не сдвигает список в узкую колонку. На мобильном экране выбор занимает отдельную строку; контролы подписаны для экранного диктора.
- В конференции появились чат, очередь вопросов и список участников с поиском и страницами.
- Участник может поднять или опустить руку. Организатор и пользователь с `conference.manage` могут опустить чужую руку, отметить вопрос отвеченным, закрыть или вернуть его в очередь.
- Сообщения и вопросы сохраняются в MySQL. После встречи доступна кнопка «История чата и вопросов» без подключения камеры, микрофона или LiveKit. Переключатель «Все встречи и история» показывает и давние встречи.
- «Скачать всё» экспортирует весь чат и вопросы в UTF-8 TXT, включая незагруженные в браузере сообщения. Экспорт проверяет те же права, что и просмотр истории.
- Повтор отправки после сетевого сбоя использует `client_id`, чтобы не дублировать запись. Ревизии вопросов защищают интерфейс от устаревших ответов при модерации.
- Изменения передаются через серверные события LiveKit после записи в БД. Есть резервный опрос через API и восстановление сообщений при переподключении.
- Исправлены стили заголовков и кнопок внутри панели конференции, добавлены управление с клавиатуры и мобильные размеры полей ввода.
- Методы и параметры описаны в разделе «Мой API», `/api/openapi.json` и [API.md](API.md).

## Обновление с 0.7.0

Нужна миграция `009_conference_collaboration.sql`. Она добавляет историю сообщений и поля участия в конференции. Дополнительные сервисы или секреты для чата не нужны: используются существующие MySQL и LiveKit.

Перед обновлением сохраните резервную копию MySQL. Используйте одинаковый образ 0.8.0 для приложения, worker и миграций. Соединения MySQL и часы контейнеров должны работать в UTC; интерфейс отображает время в часовом поясе браузера.

При локальной сборке из корня нового исходного кода:

```bash
docker compose up -d --build --wait
docker compose logs --tail=80 migrate
docker compose ps
```

При использовании собственного registry сначала соберите и загрузите образ 0.8.0, обновите `KONTUR_IMAGE` в `.env`, затем:

```bash
docker compose pull app worker migrate
docker compose up -d --no-build --wait
```

Helm использует pre-upgrade Job для миграций. Укажите репозиторий своего образа и сохранённые values/секреты:

```bash
helm upgrade --install kontur-work ./deploy/helm/kontur-work \
  --namespace kontur-work --create-namespace \
  --values production-values.yaml \
  --set image.tag=0.8.0 \
  --wait --timeout 15m
```

Параметры внешней БД, Redis, S3, LiveKit и секретов описаны в [инструкции Helm](../deploy/helm/kontur-work/README.md); standalone — в [инструкции Docker](../deploy/standalone/README.md). Не отключайте миграцию при первом обновлении на 0.8.0. Обновите вкладки участников, чтобы получить новый клиент и медиатокен.

## Проверка

```bash
npm run test:conferences
npm run quality
npm run build
```

Тесты выполняют настоящие обработчики API с заменой инфраструктуры. Проверяются права, scope и API-политика, ограничения ввода, курсоры истории, повторные отправки, недоступность LiveKit при сохранении, модерация, полный экспорт и поиск участников со страницами. Они не запускают MySQL и не проверяют пропускную способность медиасервера.

После обновления на тестовом окружении проверьте встречу в двух браузерах: сообщение и вопрос должны появиться у второго участника, рука — в списке, статус вопроса — обновиться после действия ведущего. Затем завершите встречу, откройте её историю, скачайте чат и проверьте отказ доступа у неприглашённого сотрудника.

## Границы проверки этой поставки

Производственная сборка и автоматические проверки выполняются отдельно от развёртывания. В рабочей среде подготовки нет MySQL, Docker/k8s и доступного браузерного предпросмотра, поэтому миграция на настоящей БД, внешний вид в браузере и медиасессия на 1000 человек здесь не подтверждены.

Для большого мероприятия используйте вебинар с небольшим числом докладчиков и нагрузочную репетицию на ваших узлах. Пагинация списка на 1000 пользователей не является проверкой 1000 медиаподключений. Комната LiveKit обслуживается одним media-узлом; число реплик само по себе не масштабирует одну встречу.
