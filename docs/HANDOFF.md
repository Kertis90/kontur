## Цель и договорённости

Контур — русскоязычная приватная платформа управления работой: проекты, задачи,
Kanban/Гант, спринты, SLA и персональные дашборды, знания, команды и коммуникации.
Основная БД MySQL. Обязательны standalone Docker и Kubernetes. В продукте нет
Service Desk и инцидент-менеджмента. Доступы задаются пользователям и группам,
включая функции API, ИИ, конференций и пространства базы знаний.

В репозитории реализованы интеграции, Allure, цели/тестирование, LDAP/OIDC,
SMTP, PWA/push, чаты и LiveKit-встречи с опциональной записью в S3.
Наличие кода не означает завершённую проверку каждого внешнего подключения.
SCIM provisioning не реализован; перечисление SCIM в источниках членства не
является наличием SCIM-сервера. Подробности — `SECURITY.md`.

В 0.18.0 добавлены постоянные пустые комнаты с входом/выходом, приглашениями
и архивом; ИИ-canvas, черновики/публикация, служебные исполнители, согласования,
генератор сценариев, лаборатория оценок, семантические источники, цитаты
и предпросмотр действий. См. `RELEASE-0.18.0.md` и `AI-AGENTS.md`.

## Что уже проверено и что осталось

На функциональной основе 0.18.0 прошли **279 тестов**, production build Next.js
и `npm run quality`. В числе тестов — 12 проверок комнат и 14 ИИ-workbench.
Это серверные поведенческие проверки с изоляцией зависимостей, не 279 браузерных
или интеграционных сценариев на настоящей БД.

При подготовке этого комплекта полный набор 279 тестов, build и quality повторно
прошли. Дополнительно проверены JSON настроек VS Code, синтаксис dev YAML,
локальные ссылки документации, правила исключения `.env` и совпадение всех
35 SQL-файлов с базовым коммитом. Локальная проверка выполнена на Node 24.19.0;
production Dockerfile использует Node 22. Проверка YAML не заменяет запуск Compose.

В среде подготовки нет MySQL, Docker, Helm CLI и Chromium. Поэтому здесь не
подтверждены реальные миграции 034/035, загрузка контейнеров, Helm install,
работа LiveKit/S3/STT, внешних ИИ, SMTP/LDAP/OIDC, браузерная вёрстка и нагрузка.
Исходники подготовлены; фактического развёртывания этого релиза на вашем сервере
не было. Вместимость 1000 участников не подтверждена нагрузочным тестом.

## Ближайшие шаги для новой рабочей сессии

1. Поднять отдельный dev-стенд по `DEVELOPMENT.md`, выполнить все 35 миграций,
   seed и вход bootstrap-владельцем. Пройти администрирование и возврат из шаблонов.
2. Прогнать обновление копии вашей существующей БД. Проверить диагностику 013/021
   и применение 034/035, сохранив backup и ключ шифрования.
3. Проверить комнаты несколькими пользователями: ноль участников при создании,
   вход, выход последнего, приглашение, архив, запрет чтения/файлов/push после выхода.
4. Подключить свой ИИ endpoint: черновик → тест → публикация → запуск → согласование
   → рестарт worker → продолжение; отдельно запреты исполнителя, бюджет и preview.
5. Пройти UI на 360–390 px и десктопе: чат/поле ввода, Kanban drop target,
   backlog selects, навигация администрирования, комнаты, canvas и панели ИИ.
6. На полном Compose-стенде проверить конференцию, запись в S3, расшифровку
   и изложение, затем многопользовательский прогон по `deploy/LARGE_MEETINGS.md`.

Список — приоритет проверки поставки, а не утверждение, что найдены новые баги.
Дальнейшие функции выбирать по результатам этих проверок и новым задачам владельца.
