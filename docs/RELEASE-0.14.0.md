# Контур Work 0.14.0

Пакет развития после 0.13.0. Основной стек сохранён: Next.js/Node.js, MySQL, Redis, приватный S3 и LiveKit.

## Новые возможности

| Область | Что появилось |
| --- | --- |
| Интеграции | Личные CalDAV-календари; двусторонняя синхронизация существующих задач GitLab; сопоставления и разбор конфликтов |
| SLA | Предупреждения, нарушения, эскалации по рабочим минутам, адресаты и события автоматизации |
| Автоматизация | Действие отправки через подключение, предварительный просмотр получателя и отдельное право integration.send |
| Контроль интеграций | Состояние доставки, уведомления об ошибках/восстановлении, история изменённых настроек |
| Тестирование | Кейсы, шаги и ожидаемые результаты, планы, снимки прогонов, дефекты, история проверок, результаты JUnit |
| Цели и OKR | Владельцы, сроки, ручные показатели или процент завершения связанных задач, веса и журнал обновлений |
| Поиск | Embeddings через свой профиль ИИ, индекс MySQL, поиск по смыслу в задачах, знаниях и расшифровках с проверкой доступа |
| Импорт Jira | Предварительная проверка, загрузка файлов, исходная история и комментарии, связи, возобновление и отчёт сверки |
| Эксплуатация | Экран состояния, метрики Prometheus, ServiceMonitor и панель Grafana, шифрованные копии, восстановление на отдельном сервере, Helm CronJob |
| Конференции | Воспроизводимые сценарии нагрузки LiveKit и приложения для отдельного стенда, включая профиль 1000 участников |

Все новые методы включены в справочник «Мой API» и `/api/openapi.json`. В примерах используется адрес текущей установки; бинарная загрузка показывает `--data-binary`.

## Обновление существующей установки

1. Зафиксируйте текущий образ и сделайте копию MySQL и S3. Сохраните отдельно APP_ENCRYPTION_KEY, AUTH_SECRET и конфигурацию развёртывания.
2. Соберите образ из этого исходного кода. Для Compose: `docker compose build`.
3. Остановите записи приложения и фоновые обработчики на время миграций. Для Compose: `docker compose stop app worker recording-worker`.
4. Выполните `docker compose run --rm migrate`. Новые миграции — **022–029**; уже применённые будут проверены по контрольной сумме и пропущены. Старые миграции не редактировались. Диагностика частичной 013 остаётся в [DATABASE-UPGRADES.md](DATABASE-UPGRADES.md).
5. Запустите `docker compose up -d`. В Kubernetes обновите image.tag, примените migration Job и дождитесь rollout приложения и обоих типов worker согласно README chart.
6. Проверьте `npm run db:status`, вход администратора, основные проекты и экран «Администрирование → Состояние платформы».

Для библиотек тестирования и OKR назначьте новые проектные права; для индексации, календарей и эксплуатации — права рабочего пространства. Владелец и администратор получают их автоматически. **Уже созданные API-токены не расширяются:** новые scopes нужно явно разрешить политикой пользователя и выдать новому токену.

Новые подключения, embeddings, резервное копирование и ServiceMonitor выключены до настройки. Секреты внешних сервисов и доступ к серверу пользователя в этом обновлении не подставляются.

## Границы реализации и проверки

- CalDAV: одна неповторяющаяся встреча на объект, UTC/TZID, собственный RSVP. Нет календарного discovery, серий и переноса произвольного набора компонентов; неподдерживаемые события вызывают ошибку без перезаписи. Изменение параметров встречи разрешено организатору/управляющему для scheduled.
- GitLab: title, description, due_date, один исполнитель, открытый и закрытый этап. Новые внешние issues не создаются. Выполняются проверки до/после записи; атомарную защиту от всех сторонних клиентов GitLab не гарантирует.
- Семантический поиск приближённый: до 1000 кандидатов, 15 материалов, до 128000 символов на источник. После изменения текста он исключается до обновления индекса. Индексация запускается вручную и учитывается в бюджете ИИ; сторонний векторный сервер не требуется.
- OKR принадлежат отдельному проекту; связи задач внутри проекта. Межпроектной иерархии корпоративных целей нет.
- Импорт Jira работает с подготовленным JSON и отдельно загруженными файлами, до 500 задач/2,5 МБ за пакет. Произвольные URL вложений не скачиваются. Уже импортированные задачи не перезаписываются. Неизвестные типы связей и циклы отмечаются в отчёте. Частичный экспорт истории распознаётся по total.
- Резервная копия скрипта содержит MySQL. Для восстановления всей платформы нужны ещё резервирование S3, ключей и конфигурации. PITR — отдельная процедура оператора с непрерывным архивом binlog.

Проверки исходного кода и сборка выполняются отдельно от эксплуатации. Реальные MySQL, Docker, Helm, CalDAV/GitLab, embeddings, устройства и встречи на 1000 участников требуют стенда. Этот выпуск не означает автоматического обновления сервера пользователя.

Руководства: [качество, OKR и поиск](QUALITY-OKR-SEARCH.md), [интеграции и синхронизация](SYNC-AND-SLA.md), [импорт](JIRA-IMPORT.md), [эксплуатация](OPERATIONS.md), [нагрузочные сценарии](../scripts/load/README.md).

Для проверки на настоящем MySQL подготовлен изолированный сценарий (в текущем окружении не запускался):

```bash
docker compose -f deploy/tests/expansion.compose.yaml up --build --abort-on-container-exit --exit-code-from expansion-test
```

Он применяет все миграции к временной БД и проверяет повтор результата тестирования, OKR и возобновляемый импорт без дублирования. Production-адреса в сценарии не используются.

Итоговая проверка кода: **179 тестов прошли**, проверка качества CSS/PWA/OpenAPI и production-сборка Next.js завершились успешно. YAML Compose/values/monitoring и JSON Grafana разобраны парсерами; это не заменяет helm lint и запуск контейнеров. Визуальная проверка в браузере и на устройствах не выполнялась.
