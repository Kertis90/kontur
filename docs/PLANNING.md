# Планы и идеи

В разделе «Планирование и инструменты → Планы и идеи» можно подготовить новый
проект или инициативу внутри работающего проекта. План содержит описание,
плановые даты и цель; его состав — эпики и задачи. У каждой карточки есть
приоритет, ответственный, оценка в часах или баллах, даты и своя связанная цель.

## Как пользоваться

1. Нажмите «Новый план». Выберите работающий проект либо новый проект-черновик.
2. Опишите ожидаемый результат и выберите доступную цель.
3. Добавьте эпики, затем задачи через «+ Задача» рядом с нужным эпиком.
4. В работающем проекте карточки сразу появятся на доске в колонке «Планируется».
   Рабочие задачи этого же проекта продолжают выполняться независимо.
5. Для проекта-черновика сначала нажмите «Создать рабочий проект»: задайте ключ и
   процесс или выберите существующий проект. Карточки останутся запланированными.
6. Нажмите «Начать работу» у эпика или задачи. Создастся обычная рабочая карточка,
   связанная с планом, и исчезнет из колонки «Планируется». Для вложенной задачи
   сначала начните родительский эпик. Повторное нажатие не создаёт дубликат.

Начатую карточку редактируют в обычной задаче; её заголовок в плане открывает
рабочую карточку. Связь с целью остаётся в плане. Она сама по себе не изменяет
числовые показатели OKR: учёт задачи в ключевом результате настраивается в целях.

## Кто видит план

В работающем проекте нужны доступ к проекту и отдельное право «Просмотр
запланированных эпиков и задач» (`planning.view`). Для изменения нужно также
«Изменение планов и начало работы» (`planning.manage`). Обычные участники не
получают новые права автоматически; руководители проектов, системный владелец
и администратор имеют их по правилам своих ролей. Права назначаются через
существующие роли пользователей и групп.

Создание проекта-черновика требует `planning.create`. Его автор выбирает участников
через кнопку «Участники» и отдельно разрешает изменение. До выбора рабочего
проекта черновик доступен только этим участникам и системным администраторам.
После привязки действуют права рабочего проекта: бывшее приглашение в черновик
не выдаёт доступ к самому проекту. Участников и права нужно назначить в проекте.

Для начала работы дополнительно нужны права создания задач; для назначения
ответственного — назначения исполнителей. Действуют обычные ограничения схемы
типов и рабочего процесса. Ссылки на цели проверяются отдельно и скрываются,
если сотрудник больше не имеет доступа к цели.

## Архив, сохранение и ограничения

Запланированный элемент можно отменить и вернуть в планирование. Эпик с
неотменёнными задачами нельзя отменить до изменения его состава. Архивный план
исчезает с доски, сохраняет историю и возвращается кнопкой «Вернуть из архива».
Изменение другой вкладкой вызывает сообщение о конфликте; оно не перезаписывает
чужие данные. Сохранения и начало работы фиксируются в журнале аудита.

На план допускается до 2000 элементов, вложенность — эпик → задачи. Список
показывает последние 500 планов, доска — до 500 запланированных элементов; при
достижении ограничения появляется пояснение. Черновики хранятся отдельно и не
попадают в обычные отчёты, поиск задач и источники ИИ до начала работы.

API описан в `/api/openapi.json`: отдельные `planning:read` / `planning:write`,
для начала работы также `tasks:write`, для выбора проекта — `projects:write`,
для чтения связанных целей — `objectives:read`. Права пользователя действуют
вместе с разрешениями токена.

Хранение добавляет миграция `037_planning_drafts.sql`; дополнительные сервисы
и переменные окружения не требуются ни для Compose, ни для Helm.
