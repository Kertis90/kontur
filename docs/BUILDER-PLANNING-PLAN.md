# Конструктор агентов, оформление и планирование

Запрос владельца от 23 сентября 2026, после версии 0.19.0.

## Возможности для пользователя

Полноценная схема ИИ-агента: добавление триггера, источников, анализа, условий,
действий и завершения; отдельное перемещение блоков, настройка связей и ветвей,
сохранение, проверка, публикация и выполнение сценария. Внешний вид чата и
боковой навигации должен использовать пространство окна без пустых высоких
областей и узких вложенных полос прокрутки избранного.

Планирование — отдельные черновики проектов, эпиков и задач с привязками к
целям. В работающем проекте могут одновременно существовать рабочие задачи
и ещё не принятые в работу запланированные эпики.

## Обязательные условия

- Сохранить MySQL, Compose и Helm, русский интерфейс, мобильную вёрстку,
  красный акцент, существующие агенты и их опубликованные версии.
- Не ослаблять права, бюджеты ИИ, проверки источников, согласования действий,
  защиту от повторного выполнения и правила версии записей.
- Запланированные эпики и задачи сразу отображаются на доске отдельной колонкой
  «Планируется». Они хранятся отдельно до начала выполнения, чтобы права
  планирования не раскрывали черновые данные через обычные задачи, отчёты и ИИ.
- Связи с целями и объектами других проектов требуют актуального доступа.
- Новые миграции после 036; существующие миграции сохраняются побайтово.
- Настоящие внешние действия агента проверяются через существующие механизмы
  разрешений и подтверждений, не заменяются визуальной имитацией.

## Решения владельца

- Запланированные задачи сразу видны на доске со статусом «Планируется».
- Видимость: доступ к проекту плюс отдельные права планирования.

## Контракт реализации

- Конструктор сохраняет прежний формат конфигурации с добавлением `flow.entry`,
  координат триггера/источников/итога и блока `action`. До 32 блоков, до 12
  обращений к модели. Связи образуют направленную схему без циклов. Пустые связи
  прежних версий сохраняют последовательное выполнение. Только пройденные
  блоки действий добавляют предложения; итоговая модель не добавляет действия
  вне ветвей. Согласование, права, лимиты и единственная транзакция применения
  остаются общими для всего запуска.
- План — проект-черновик либо инициатива в существующем проекте. Содержит эпики
  и задачи, сроки, приоритеты, оценки, ответственных и связи с целями. Вложенность:
  эпик → задачи. Запланированный эпик может сосуществовать с рабочими задачами.
- Проектный план требует `planning.view` для чтения и `planning.manage` для
  изменений, вместе с `project.browse`. Для проекта-черновика есть участники с
  правом просмотра/изменения; создание требует `planning.create`. Владелец и
  системный администратор сохраняют доступ. Цели проверяются отдельно.
- `GET/POST /api/work/plans`, `GET/PUT /plans/{id}`, `POST /plans/{id}/items`,
  `PUT /plans/{id}/items/{itemId}`, `POST /plans/{id}/items/{itemId}/start`,
  `POST /plans/{id}/start-project`. Все изменения существующих записей требуют
  revision. Начало работы сохраняет ссылку на созданный объект и повторно
  возвращает тот же объект. Создание задач использует общие проверки проекта.
- Доска запрашивает запланированные карточки только при наличии права чтения
  планирования. Обычные выдачи задач не подмешивают черновики. Начатая задача
  появляется в рабочем процессе проекта и пропадает из колонки планирования.
- Проверки: циклы/ветви/продолжение агента, конфликты версий, чужое пространство,
  отзыв доступа и повтор запуска плана, реальная MySQL, браузер на двух размерах.

## Текущее состояние

В `.env` добавлено 19 параметров: обработка ИИ, записи, внутренние подключения,
резервирование/восстановление, телефония и два образа MinIO. Все 39 прежних
значений и исходные байты сохранены. Параметры внешних подключений и необязательные
секреты оставлены пустыми для последующей настройки; в Git файл не включается.
Оба профиля Compose проходят проверку конфигурации без запуска сервисов.
