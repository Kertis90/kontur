# Контур Work 0.21.0

24 сентября 2026. Планирование, личная навигация и визуальный конструктор.
Развитие Jira исключено из этой версии по решению владельца.

## Конструктор и проверка агентов

Исправлено перемещение блоков после выбора точки связи: незавершённое соединение
больше не блокирует перетаскивание. Стрелки автоматически выбирают сторону по
расположению блоков. Можно выбрать отдельную связь и вручную закрепить её выход
и вход сверху, справа, снизу или слева. Положение и стороны сохраняются в схеме;
доступны отмена и повтор изменений.

В редакторе можно открыть прежний запуск и выбрать блок: увидеть его вход,
результат, выбранную ветвь, ошибку, длительность и расход токенов. Для новых запусков
входы сохраняются зашифрованно. Проверка по сохранённым данным повторно проверяет
права и версии источников, расходует общий бюджет и не применяет действия.

Библиотека общих частей позволяет сохранить сценарий проекта и добавить его
в другой агент того же проекта. Каждый вызов закреплён за конкретной версией:
обновление библиотеки не меняет существующие агенты. Вложенность ограничена тремя
уровнями, общий сценарий — 128 шагами; права и лимит обращений к модели общие.

## Планы и общая карта

Для плана доступны ожидаемый результат, эффект, усилия и обоснование приоритета.
Согласующие назначаются явно и принимают решение о конкретном составе. Изменение
состава, сроков, зависимостей или доступа согласующего делает решение устаревшим.

Плановые задачи можно связывать между собой и с рабочими задачами. Циклы связей
блокируются; при начале работы зависимости переносятся в рабочие карточки.
Сначала нужно начать необходимые предшествующие элементы и родительский эпик.

Общая карта объединяет доступные планы и рабочие задачи на шкале времени.
Сценарий сдвига пересчитывает зависимости без записи в базу. В отдельном окне
показываются прежние и новые даты; пользователь выбирает, что сохранить.
Запись выполняется целиком либо отменяется при конфликте версий. Прогноз загрузки
учитывает резервы времени, оценки планов и календари команды.

ИИ-помощник предлагает эпики, задачи, зависимости, критерии готовности и
предположения. Сохранение выбранных предложений — отдельное действие пользователя.
Доступ к целям, исходный состав плана, бюджет и повтор запроса проверяются сервером.

## Навигация и документация

Вместо первых пяти проектов — собственное избранное: проекты, доски, планы и
статьи. Порядок меняется перетаскиванием или кнопками. В боковой панели видны
первые пять закреплений, полный список открывается отдельно. Отзыв доступа
скрывает недоступные объекты.

README переработан в основное руководство: возможности, первый запуск,
настройка ИИ, доступ, обновление, резервирование и разработка.

После отказа официальных реестров готовых образов MinIO добавлена сборка сервера
и клиента из закреплённых исходников с проверкой SHA-256. Версии и формат данных
сохранены. Compose и тестовый стенд используют эту сборку; Helm продолжает
работать с внешним S3. [Сборка хранилища](../deploy/storage/README.md).

## Обновление

Сделайте резервную копию MySQL, S3 и конфигурации с ключом шифрования, затем
обновите образ, приложение и оба worker. Порядок работы с миграциями —
в [руководстве обновления БД](DATABASE-UPGRADES.md).

| Миграция | Изменение |
| --- | --- |
| 038 | Личное избранное и версия списка. |
| 039 | Оценки, зависимости и согласования планов. |
| 040 | Предложения ИИ для планирования и защита от повторного применения. |
| 041 | Версии общих частей сценария, зашифрованные данные запуска и расход по шагам. |
| 042 | Происхождение цели в предложениях плана, чтобы проверять доступ после изменения плана. |
| 043 | Защита от повторного сохранения сценария сроков. |

Выпущенные миграции 001–037 не менялись. Новых обязательных переменных окружения
нет. Нужен прежний `APP_ENCRYPTION_KEY`; модель и её ключ настраиваются в интерфейсе.
Старые запуски без сохранённых входов доступны в истории, но не подходят для повтора
на прежних данных. Миграция 042 отменяет предложения предварительной версии 0.21,
для которых нельзя подтвердить исходную цель; их нужно подготовить заново.

## Проверки и границы

Результаты проверки текущей поставки записаны в [плане работ](WORKSPACE-0.21-PLAN.md).
Интеграционные тесты используют отдельную MySQL, Redis и S3. В проверках ИИ
подменяется только ответ модели; права, версии, очереди и запись проверяются реально.

Рабочая установка владельца не обновлялась. Реальный провайдер модели, LiveKit,
нагрузка и Kubernetes требуют отдельной проверки в целевой среде.
Ожидание внешнего события и отдельные ветви ошибок не входят в этот выпуск.
