# Контур Work 0.22.0 — выбор базы данных

25 сентября 2026. Приложение можно установить с MySQL 8.4 или PostgreSQL 18.
Выбор задаётся через `DB_ENGINE=mysql|postgres`; MySQL остаётся значением
по умолчанию. Один образ приложения обслуживает оба варианта.

## Что изменилось

- Добавлены подключение PostgreSQL, отдельные миграции, ограничения целостности,
  история задач, отзыв сессий и токенов, блокировки и атомарные операции.
  Выпущенные миграции MySQL 001–043 сохранены побайтово.
- Подготовлены профили Docker Compose и настройки Helm. В PostgreSQL-контейнере
  приложение работает с отдельной учётной записью без прав администратора сервера.
- Добавлены зашифрованные копии PostgreSQL, проверка целостности и восстановление
  в отдельную пустую базу. Тип базы записывается в копию и проверяется при восстановлении.
- Общие запросы адаптированы для обеих БД. Исправлены запросы поручений встреч
  и сохранения вложений существующего импорта Jira; новых возможностей Jira нет.
- Уточнена защита автоматического применения ИИ: пробные запуски, ручные
  согласования и некорректные значения флагов не допускаются к автоматической записи.
- Дополнены примеры окружения, README, руководство выбора БД и проверки CI
  для MySQL и PostgreSQL. В локальный `.env` добавлены только отсутствующие параметры.
- Удалены старые логи и временные отчёты из рабочей папки. Исходники, зависимости,
  `.env`, сборка и пользовательские данные сохранены; секреты не публикуются.

## Запуск и ограничения

[Настройка MySQL/PostgreSQL](DATABASES.md) описывает Docker, разработку, Helm,
миграции и копии. Для новой установки PostgreSQL после заполнения `.env`:

```bash
docker compose -f compose.yaml -f compose.postgres.yaml up -d --build --wait
```

Смена `DB_ENGINE` не переносит существующие записи. Рабочая база и работающая
установка владельца не обновлялись. Перенос данных MySQL в PostgreSQL потребует
отдельной процедуры со сверкой. PostgreSQL должен поддерживать ICU; проверена
ветка 18. Для восстановления на момент времени требуется отдельно настроить WAL.

Проверки выполнялись на изолированных стендах. Внешняя ИИ-модель, реальная
видеосвязь LiveKit и развёртывание в Kubernetes этим выпуском не проверялись.
