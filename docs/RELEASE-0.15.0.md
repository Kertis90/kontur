# Контур Work 0.15.0

## Изменения

- Длинное боковое меню прокручивается независимо от рабочего раздела, нижние пункты и профиль остаются доступны.
- Выровнены контейнеры страниц «Цели и OKR», «Тестирование», «Интеграции». Исправлены переносы заголовков, отступы карточек и фильтров, формы, списки выбора и узкие экраны.
- Добавлена постоянная панель чата справа: поиск, счётчики непрочитанных, переписка, файлы, переход в полный чат. На телефонах — компактная кнопка и панель с учётом экранной клавиатуры.
- Полный чат и панель используют общее поле ввода. История открывается с последних сообщений, поддерживает подгрузку старых записей и сохраняет позицию при чтении. Закрытый чат не помечается прочитанным.
- Настройки PWA и уведомлений доступны через ⚙ справа. Внедрена добровольная подписка Web Push и серверная доставка с проверкой прав и сессий. Без настроенного push доступен режим уведомлений при открытом приложении.
- Обновлены manifest, обработчик уведомлений и офлайн-кэш. HTML оболочки больше не возвращается вместо отсутствующих файлов JavaScript/CSS.
- Добавлены методы API подписки устройства и отметки прочтения, переменные Compose и параметры Helm. [Инструкция](PWA-AND-CHAT.md).

## Обновление

Есть новая миграция `030_browser_notifications.sql`: курсор прочтения чатов и таблица зашифрованных push-подписок. Старые миграции **001–029 не изменены**; исправление восстановления 021 из версии 0.14.2 сохранено. Изначальные курсоры вычисляются по прежней отметке `last_read_at`; после обновления подтверждается точный ID сообщения.

Сохраните резервную копию БД, прежнее окружение, тома и имя Compose-проекта. Обновляйте код в существующем каталоге установки. Если используется `-p`, добавляйте прежнее имя во все команды. Выполняйте следующую команду только после успешного завершения предыдущей:

```sh
docker compose stop app worker recording-worker
docker compose build migrate
docker compose run --rm --no-deps --entrypoint node migrate scripts/migrate.mjs --status
docker compose run --rm --no-deps --entrypoint node migrate scripts/migrate.mjs
docker compose up -d --wait
```

`build migrate` собирает общий образ app/worker/recording-worker. Если ваши override задают разные образы, обновите каждый из них. Настроенная внешняя MySQL должна быть доступна мигратору. Не запускайте архив как новый Compose-проект с пустыми томами и не выполняйте `down -v`.

В Kubernetes соберите и загрузите образ `0.15.0` в свой registry, обновите chart/image.tag, сохранив values и секреты. Перед миграцией приостановите запись app и worker: pre-upgrade hook не останавливает старые реплики автоматически. Фоновый push по умолчанию выключен; включение и VAPID-ключи описаны в [PWA-AND-CHAT.md](PWA-AND-CHAT.md). Установка обновления сама по себе не запрашивает разрешения у пользователей.

При прерывании новой 030 мигратор блокирует слепой повтор: DDL MySQL мог уже сохраниться. Не удаляйте журнал и не изменяйте SQL; сохраните `--status`, сравните фактическую схему с 030 на копии БД и используйте [DATABASE-UPGRADES.md](DATABASE-UPGRADES.md). Автоматическое восстановление по строгой схеме по-прежнему предусмотрено для 013/021.

## Проверка

Проверяются общий набор регрессионных тестов, права и курсоры чатов, регистрация push, ограничения endpoints, шифрование, отзыв сессии, тихие часы, ошибки доставки, поведение service worker и production-сборка. Итог: **215 тестов прошли** (24 файла, каждый запущен отдельно с проверкой итогового счётчика), проверка семи CSS-файлов/PWA/API и production-сборка Next.js успешны. Compose, Helm values и Chart проверены YAML-парсером; это не заменяет helm lint и запуск контейнеров.

В этой среде нет запущенного MySQL/Docker/Kubernetes и доступного браузерного предпросмотра. Здесь не подтверждены выполнение 030 на реальной БД, внешний push, установка на телефон и визуальное поведение с клавиатурой. Для них предусмотрены инструкции проверки на стенде; сборка не заменяет эти проверки. Сервер пользователя автоматически не обновляется.
