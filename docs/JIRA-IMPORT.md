# Расширенный импорт Jira

Доступ: «Администрирование → Импорт из Jira» либо «Планирование и инструменты → Работа с данными → Импорт». Требуются import.manage и task.create в проекте. Для файлов — attachment.manage, для связей — task.edit; назначение исполнителя проверяет task.assign.

## Подготовка

Подготовьте JSON с массивом issues или самим массивом задач. Пакет ограничен 500 задачами и 2,5 МБ. Большой экспорт разделите на пакеты с уникальными ключами. Поля:

| Данные Jira | Назначение |
| --- | --- |
| key | Уникальный внешний ключ внутри проекта назначения |
| fields.summary/description | Название и описание; текст либо ADF content |
| fields.status.name | Сопоставление с этапом Контура |
| fields.priority.name | Приоритет |
| fields.assignee.emailAddress/displayName | Существующий активный сотрудник; неоднозначное имя отмечается предупреждением |
| fields.duedate | Календарный срок YYYY-MM-DD |
| fields.comment.comments | Полные исходные комментарии |
| changelog.histories | Изменения, авторы, даты и значения полей |
| fields.attachment | id, filename, size, mimeType; сами байты загружаются отдельно |
| fields.issuelinks | outwardIssue/inwardIssue.key и type.name |

Если экспорт постраничный, соберите все страницы комментариев и истории. total больше числа записей вызывает предупреждение о неполном экспорте. Учётные записи Jira не создаются автоматически, старые авторы истории остаются под исходными именами.

## Процесс

1. Выберите проект и файл, сопоставьте неизвестные этапы. Повторите проверку. Ошибочный предварительный просмотр не создаёт задач.
2. Сохраните подготовленный импорт. Проверьте список и предупреждения. Для переноса файлов оставьте соответствующий флаг включённым.
3. Загрузите каждый файл к строке манифеста. Сервер ограничивает размер MAX_ATTACHMENT_BYTES, сравнивает его с экспортом, вычисляет SHA-256 и сохраняет объект в приватный S3. URL из Jira не используется для скачивания. Повтор тех же байтов безопасен, подмена другим файлом отклоняется.
4. Подтвердите запуск. Worker создаёт по одной задаче с историей и ссылками на уже загруженные файлы в транзакции. Затем отдельным проходом связывает задачи.
5. Скачайте JSON-отчёт сверки. Проверьте числа созданных/пропущенных задач, отсутствующие ссылки и частичные данные. При ошибке исправьте права, недоступность инфраструктуры или процесс и нажмите «Продолжить».

Остановка сохраняет уже обработанные задачи, позицию и загруженные файлы для продолжения. Она не откатывает ранее подтверждённые задачи. Отмена до загрузки всех файлов требует нового предварительного просмотра. Подготовленные данные хранятся зашифрованными; автоматически удалять незавершённый импорт по таймеру система не будет.

Повтор внешнего ключа внутри проекта не перезаписывает задачу, её историю и вложения. Полные импорты без дублей дают новые задачи; поля существующих задач этим инструментом не синхронизируются. Для обновления используйте штатный API или интеграцию.

Поддержаны связи Blocks, Relates/Relates to, Duplicates и указанные в интерфейсе русские аналоги. При блокировке учитывается направление. Неизвестный тип, отсутствующая целевая задача, самоссылка или цикл не создают опасную связь и отражаются в отчёте. Межпроектные ссылки и пользовательские типы требуют последующей ручной настройки. Если цель появится только в следующем пакете, ранее пропущенная связь не будет достроена автоматически.

История находится в карточке задачи в блоке «История и комментарии из Jira» с постраничной загрузкой. Исходные даты и авторы не подменяют журнал действий пользователей Контура. Если у пользователя закрыт доступ к части атрибутов проекта, импортированная история изменения полей скрывается целиком: поля Jira ещё не сопоставлены с ограничениями Контура. Комментарии сохраняют обычные права проекта.

## API

Новые scopes: imports:read/imports:write. Фоновая обработка проверяет активность пользователя, срок/отзыв токена, разрешённые scopes и права проекта. Токен для чтения импортированной истории использует tasks:read и обычный доступ к задаче.

Для загрузки используйте полные значения своей установки:

```bash
curl --request PUT \
  --url "https://projects.example.ru/api/work/jira-imports/12/files/34" \
  --header "Authorization: Bearer $KONTUR_TOKEN" \
  --header "Content-Type: application/octet-stream" \
  --data-binary "@specification.pdf"
```

Все методы, поля revision/preview_hash и примеры доступны в «Мой API» и [API-WORK.md](API-WORK.md).
